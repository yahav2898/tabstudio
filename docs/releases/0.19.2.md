TabStudio 0.19.2 fixes what 34 more public repositories ran into when they were opened, built and run as a person would
on a tablet: Node and Python web apps that did not serve, native projects that Ctrl+Shift+B never built, .NET solutions
whose MSBuild was read too simply, and projects that cannot run on a tablet but were compiled anyway. Hidden spinners
no longer keep the IDE drawing.

## Fixed

- **Node dev servers open in the web preview.** Vite and Next.js bind `localhost`, which is IPv6's `::1` alone on
  Android's Alpine environment and most Linux computers, and TabStudio only tried `127.0.0.1`. A server's address is
  now probed, IPv4 first, then IPv6. A `start` script that serves a production build (`next start`, `nuxt start`,
  `vite preview`, `astro preview`, `remix-serve`) is passed over for the `dev` script, since it fails until a
  production build exists; it still runs when it is all there is. vercel/next-learn's dashboard and Vite's React
  template now answer their first page.
- **Python web apps run without a launcher file.** A Flask application package (`create_app` or `Flask(` in its
  `__init__.py`, as in Flask's own tutorial) runs with `flask run`, and a FastAPI or Starlette app in `main.py`,
  `app.py`, `app/main.py` or `src/<package>/main.py` runs with `uvicorn <module>:app` when the project depends on
  uvicorn (and says so when it does not). The Python a project's `.venv` gets now also follows the pins in
  `poetry.lock` and `uv.lock`, so fastapi-realworld's asyncpg 0.26 gets Python 3.10, which it has wheels for. A
  package whose C code does not build against a newer Python says so in one line, and suggests an older Python, never
  the one that just failed.
- **Ctrl+Shift+B builds every language.** It built C# projects, Android, embedded firmware and Microchip projects only;
  for Rust, Go, Java, CMake and Make it did nothing and reported no errors. It now runs the build F5 runs first, and
  stops: the errors go to the Error List and the Output says whether it succeeded. A project that runs from its
  source, such as Python, says there is nothing to build.
- **The right program of a CMake or Make project runs.** With several executables, TabStudio picks the one defined
  in the top-level `CMakeLists.txt` (cJSON's `cJSON_test`), the one named as the `program` of a `.tabstudio/launch.json`
  configuration, or the one the open file belongs to. When it still cannot choose, it lists them in one line and says
  how to pick one, instead of reporting an exit code from a program that never ran.
- **F5 starts what a person would.** A .NET solution's startup project is a Blazor or Razor app first, then a GUI app,
  then an API, then a console app; projects in `docs`, `scripts`, `tools` or `tests` folders come last, and tests,
  benchmarks, build scripts, Aspire AppHosts and platform heads are never chosen. dotnet/eShop starts `WebApp`,
  Terminal.Gui `UICatalog`. When nothing in a solution starts on a tablet, the status bar says why in one line. A
  `package.json` that only holds linters no longer wins over the folder's real program (mdBook starts its Rust binary).
- **Projects that need a platform workload are explained, not compiled.** .NET MAUI, Xamarin and UWP projects and
  `-android`, `-ios`, `-maccatalyst`, `-tvos`, `-macos` and `-tizen` heads are left out of builds and analysis with one
  Error List line (TS2005) and an honest Compatibility Doctor row; before, a MAUI app compiled every `Platforms/*`
  folder together into dozens of errors, and the Doctor called it "coming in an update". A project that references
  one is skipped with one line too. BenchmarkDotNet projects, TUnit tests and worker services say in one line why they
  do not run here.
- **MSBuild is read as MSBuild reads it.** Imports written with `$([MSBuild]::GetPathOfFileAbove(...))` are followed,
  so nested `Directory.Build.props` files reach the repository's root one (Refit's examples, Terminal.Gui's tests,
  StronglyTypedId), and `Version` gets the SDK's default from `VersionPrefix` and `VersionSuffix`.
  `Directory.Packages.props` is evaluated with its conditions, `Choose`/`When`, imports and `Update`, and a
  `VersionOverride` wins over the central version. Conditions are evaluated for the framework TabStudio compiles
  (`net10.0` when the project lists it), not for the first one listed. `$(Property)` references in `Compile`,
  `EmbeddedResource` and `AvaloniaResource` patterns are expanded (Spectre.Console's generated files were compiled
  twice), and an explicit `Compile Include` into another project's folder, with its `Exclude`, takes every file it
  names (Dock).
- **A restore with errors keeps the packages it restored.** One missing or conflicting package used to drop every
  package from the project, so thousands of missing-type errors followed. The packages that resolved are now used,
  the restore's errors stay in the Error List, and the build warns that the rest are missing.
- **Source generators built from the repository run.** A project referenced with `OutputItemType="Analyzer"` is
  compiled from the workspace, loaded beside TabStudio's Roslyn and run for IntelliSense, live errors and builds alike,
  as Mediator's, Terminal.Gui's, Dock's, Spectre.Console's and StronglyTypedId's generators are, and a reference that
  keeps `ReferenceOutputAssembly` is compiled against too. A generator project that does not compile is one warning
  naming it (TS2006). An analyzer that .NET and a package both bring runs once, the newer one (eShop's duplicate
  `LoggerMessage` code).
- **A generator's own Microsoft.CodeAnalysis assemblies load.** Every assembly named `Microsoft.CodeAnalysis*` was
  taken from TabStudio, so a generator that ships one, such as `Microsoft.CodeAnalysis.ResxSourceGenerator`, never
  ran (CS8032). Only the compiler's own assemblies come from TabStudio now.
- **A failed package install says why.** A failed npm, cargo or go install now leaves one line naming the command and
  its first real error, and the notice over the editor, as a failed pip install did; F5 then says the packages were not
  installed before it runs. A failed `npm ci` is retried once with `npm install`, and an editable `pip install -e .`
  that the project's build backend cannot do is retried without `-e`.
- **An Avalonia app built for a newer Avalonia says so.** TabStudio runs Avalonia apps on its own Avalonia 11.3; an app
  built for Avalonia 12, such as Dock's samples, now says that in one line (TS2101) when its XAML cannot load.
- **Hidden spinners and progress bars stop animating.** Avalonia runs a style's animation whether or not its control
  is visible, and once a long operation had shown the status bar's progress bar it kept animating after it was hidden,
  so an idle IDE kept drawing frames. Every progress bar and spinner now stops while it, or a panel around it, is
  hidden.

## Install

1. Download `TabStudio-0.19.2.apk` below on your tablet.
2. Open it and allow installing apps from your browser or file manager when Android asks.

Requires Android 9 or later on 64-bit or 32-bit ARM, with 3 GB of memory or more (2 GB with TabStudio Link). It installs
as an update over 0.19.1.

## Verified

Every commit runs the unit tests of every library, headless UI tests of the real IDE in both themes, an APK build with
signature verification, and the full self test on an Android tablet emulator, which now answers Android's "isn't
responding" dialogs of other apps and fails, saying so, on its own. A test checks that an idle IDE runs no animation.

The real-repositories job now also serves dotnet/blazor-samples' Blazor Web App, runs vercel/next-learn's dashboard,
Vite's React template and an Express app on Node, the Spring REST and JPA guides on Java, a Gin API on Go and cJSON's
tests on C, each pinned to a commit with the page it must answer or the exit code it must reach. The embedded job also
builds MarlinFirmware/Marlin, ESP-IDF's blink, Zephyr's synchronization sample and the Servo library's Sweep with zero
errors. What the other repositories of the sweep still need, and why, is in the pull request that made this release.
