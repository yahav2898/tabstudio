TabStudio 0.21.7 makes the IDE smoother where people spend their time: a program or a shell that prints without
end, the Error List and Test Explorer with thousands of rows, opening a solution, and building it. Each fix was
measured before and after, in the headless IDE in CI and on CI's Android tablet emulator, and each has a test that
guards it. On the 53 pinned .NET repositories CI opens, builds and checks, the times the UI thread did not answer for
100 ms or more fell from 451 to 195, and the longest such pause from 1.5 s to 0.75 s.

## Fixed

- **A program printing in a tight loop no longer freezes the IDE.** The Output panel appended everything a program
  had printed in one job, at the UI's normal priority, one insertion per write, and a program that kept printing kept
  that job going: no tap, keystroke or frame got through until it stopped. With 20,000 lines the IDE stood still for
  38 seconds. Output now arrives in batches of at most 64 KB, one insertion for each run of text of one kind, queued
  behind input and drawing: the same 20,000 lines are all shown in 0.2 s, and the IDE never stops answering.
- **The Terminal, too.** `yes`, a large `cat` or a long build log reaches the terminal in batches of 64 KB behind
  input and drawing, instead of all at once.
- **The Error List follows a file's new analysis without rebuilding.** Every time live analysis replaced one file's
  diagnostics, which it does after every pause in typing, the Error List removed every row and added them all back,
  one notification each: 38 ms and 3,001 notifications with 3,000 rows. Now only the rows that changed are removed
  or inserted: 4.7 ms and one notification. A change to most rows, such as a filter, is one reset.
- **Test Explorer keeps up with thousands of quick tests.** Each start and each result refreshed every row above the
  test and counted every test again. Results now arrive in batches, each row refreshed once a batch: 5,000 results
  are shown in 0.07 s instead of 3.1 s.
- **Opening a solution builds only what is on screen.** The IDE built every tool window and dialog it has with each
  workspace: Locals, Watch, Call Stack, the Terminal, the Serial Monitor, Swarm, Live, Containers, Services, the
  Database Explorer, GitHub Actions, Git Changes, the search, the quick pick and more, each hidden until chosen; and
  the GitHub sign-in, TabStudio Link and Live's Join dialogs with the start screen. Each is now built the first time
  it is shown, and kept. The workspace's view starts with 1,218 visuals instead of 1,496.
- **Opening a workspace no longer reads its Services configuration on the UI thread.** The configuration was
  serialized there, the serializer's first use in the run, which held the UI thread for 3.9 to 7.4 seconds on the
  emulator; it is read and serialized in the background now.
- **Local AI suggestions no longer copy the file on every keystroke.** The inline suggestion read the whole file and
  its open neighbours on every keystroke, then waited for typing to pause, and the next keystroke threw the copy away.
  It now reads them once typing has paused.

## Measured

CI now measures what a person feels, on every commit:

- **UI stalls on the tablet emulator.** During the self test a thread of its own asks the UI thread to answer every
  16 ms; every wait of 100 ms or more is logged with what the IDE was doing (opening the solution, creating a
  document's view, loading C#, …), and `measurements.txt` lists the worst, with the slowest views to build.
- **The start's timeline.** Android's part (process and runtime), the styles, the services, the view models, the
  main view, the first frame and the start screen, logged on every start and listed in `measurements.txt`.
- **The pinned real repositories.** Each repository's report says how often and how long the UI thread stalled while
  it opened, built, showed squiggles, served and ran tests, and the summary has a column for it.
- **Headless benchmarks** beside the screenshots and in the job's log (`smoothness-*.md`): the Error List with 3,000
  rows, a program printing 20,000 lines, 5,000 Test Explorer results, Solution Explorer with 5,000 files, twenty long
  tabs, a workspace opened and closed three times, a keystroke's allocations by listener, and the start's services.
  The Output, Error List, Test Explorer and workspace view benchmarks measure the code as it was before 0.21.7 in
  the same run, for comparison.
- **Debugger steps.** The self test times three Step Overs: 98 to 382 ms each on the emulator.

## Install

1. Download `TabStudio-0.21.7.apk` below on your tablet.
2. Open it and allow installing apps from your browser or file manager when Android asks.

Requires Android 9 or later on 64-bit or 32-bit ARM, with 3 GB of memory or more (2 GB with TabStudio Link). It installs
as an update over earlier releases, from 0.19.0 on, and keeps their settings, sessions and toolchains.

## Verified

Every fix has a test: output and terminal floods reach the UI thread in bounded batches behind input and drawing,
with colors and order kept; one file's analysis changes one row of a 3,000-row Error List; 2,000 results from
parallel runner threads are shown in one batch; a new workspace builds no hidden tool window until it is chosen, and
the start screen no dialog until it opens; Local AI reads the file once for five keystrokes. The emulator's self test
and the real-repositories job record the stalls each commit.
