TabStudio 0.21.7 fixes the eight known issues earlier releases listed under "Still to do": a local AI model download
that started over after every broken connection, an extension installed unverified, the debugger's recording
changed from a background thread, a Visual Basic library that could close TabStudio, Windows Forms' `StatusBar`,
WPF's `NavigationWindow` and the rest of what Microsoft's ExpenseIt walkthrough needs, and two places in the IDE that
did not follow its text size and theme.

## Fixed

- **A local AI model download continues where it stopped.** A broken connection, a stalled one, a cancel or a
  restart of the app no longer throws away gigabytes: the download now goes through the Toolchain Store's
  downloader, which asks for the rest with a `Range` request and keeps what arrived until the file is complete. A
  connection that sends nothing for 30 seconds counts as broken and is retried, where before the download waited
  forever. A model is still installed only when its size and SHA-256 match, and a server that sends more than the
  pinned size is stopped before it fills the tablet's storage.
- **Open VSX never installs an extension unverified because its signature could not be fetched.** When the registry
  lists a signature or a public key for a version and the download of either fails, the install is refused with a
  message that says the package cannot be verified; before, it went ahead without the check. A version the registry
  publishes no signature for is unchanged.
- **The recording timeline changes the debugger only on the UI thread.** Step Back, Reverse Continue and Jump to Last
  Write searched the recording on a background thread and selected what they found there, while the timeline and
  the panels read the selection on the UI thread. The search still runs in the background; the selection is now
  made on the UI thread, and the session guards it.
- **`Environment.Exit` in a Visual Basic library ends the program, not TabStudio.** Calls in Visual Basic are now
  redirected as C#'s are, in the libraries a program loads too, so Community.VisualBasic's `ProjectData.EndApp`
  ends the program with its exit code. In a Visual Basic program, `Environment.Exit` is a warning that says so
  instead of a TS1001 error; `End` is still an error.
- **Windows Forms' `StatusBar`.** The .NET Framework's status bar, with its panels that fit their text or spring,
  `ShowPanels`, `SizingGrip` and `PanelClick`, and `Form.AutoScaleBaseSize`, which its designer files set. VBDev2Dev's
  Dots builds without its 13 errors.
- **WPF's `NavigationWindow` on OpenSilver, and WPF in Visual Basic.** Microsoft's ExpenseIt walkthrough builds and
  shows its window in C# and in Visual Basic. TabStudio adds what OpenSilver lacks to the project, as it adds
  `Application.Run`: `NavigationWindow`, on OpenSilver's frame and journal, `NavigationService.Navigate(object)`, and
  the six `AutomationEvents` members OpenSilver's enumeration does not have, such as `LiveRegionChanged`. Visual
  Basic WPF projects now build on OpenSilver and run in the web preview, as C# ones do. XAML that uses what WPF has
  and OpenSilver does not, such as `XmlDataProvider`, style triggers and the Aero2 theme, is left out with a TS7010
  warning that names it, so the rest of the window still shows; a misspelt type is still an error. What WPF writes
  differently from OpenSilver is given to OpenSilver its way: `TargetType="{x:Type Label}"`, setters named through a
  type (`Label.FontSize`) in a style without a target type, a DataGrid's `RowHeaderWidth="0"`, and dictionaries merged
  from the project's root. A `StaticResource` whose key no XAML file defines, as ExpenseIt's `CustomNavWindowStyle`,
  is named with a warning; loading the window would stop there in WPF too.
- **A TabStudio Live participant's name follows the text size.** The tag on another person's caret was drawn at a
  fixed 11 points, so Very large did not reach it. It now uses the caption size of the type scale.
- **The Windows Bridge tab follows the theme.** The card behind its QR code was a literal white; it now uses the QR
  code's own colour token, as TabStudio Link and Live do.

## Install

1. Download `TabStudio-0.21.7.apk` below on your tablet.
2. Open it and allow installing apps from your browser or file manager when Android asks.

Requires Android 9 or later on 64-bit or 32-bit ARM, with 3 GB of memory or more (2 GB with TabStudio Link). It installs
as an update over earlier 0.21 releases.

## Verified

Every fix has a regression test that failed before it: a model download broken and stalled halfway, then resumed
with a `Range` request; a registry whose signature and key cannot be fetched; the timeline's commands checked for the
thread they select on; a C# program that loads a Visual Basic library that calls `Environment.Exit`; Dots' own
designer code for its status bar; ExpenseIt in C# and in Visual Basic, built on OpenSilver and shown in a real
browser, where View goes to the report page; the Live tag at Very large; and the Windows Bridge's QR card in the
design rules.
