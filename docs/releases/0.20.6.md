TabStudio 0.20.6 is about what happens when things go wrong on a real tablet: Android ending the app in the
background, a network that stalls or hands back a Wi-Fi sign-in page, a repository with a symbolic link back into
itself, a tablet with little memory. Each fix below came from trying to make TabStudio crash, hang or lose work, and
each one has a test now that failed before it.

## Fixed

### Unsaved work survives Android ending the app

- **Switching apps while a workspace reopened lost its unsaved text.** Android saves the session whenever TabStudio
  goes to the background. While a restored workspace was still loading C#, the IDE had no documents yet, and that save
  replaced the session, including every unsaved edit, with an empty one. The session is now left alone until its
  documents are back.
- **A workspace that crashed while reopening no longer crashes every start.** If TabStudio ended while reopening the
  last workspace (out of memory with a large solution on a 3 GB tablet, for example), it reopened it again at the next
  start, and ended again. Now the start screen says what happened and offers the workspace under Recent. Opening it
  from there still restores its tabs and unsaved text.
- **Unsaved text with nowhere to go is kept.** If a file was deleted or moved while TabStudio was closed, or the
  workspace sits on storage it can no longer read (a revoked permission, a removed card), its unsaved text used to be
  dropped by the next save. It is now written to `State/Recovered`, and the Output or start screen names the file.
- **Older and damaged sessions open.** A session without a document list, as an older version or a hand edit can leave
  it, opens with no documents instead of failing.

### Errors no longer end the app

- **One operation ending as the next began could close TabStudio.** When the last running operation ended, the
  service that keeps TabStudio alive in the background stopped itself with `stopSelf()`. If Android was already
  starting the service again for the next operation (one toolchain install followed by another, say), that call took
  the new start down before it could reach `startForeground`, and Android ended the app ("did not then call
  `Service.startForeground()`"). This happened on 0.20.3's own emulator run. The service now stops only up to the
  last start it handled.

- **Unexpected errors are reported, not fatal.** On Android, an exception that nothing handled on the UI thread closed
  TabStudio, along with every running build and debug session: a dropped connection while reading a CI log, a cloud
  file the SQLite picker could not copy, an unexpected failure while opening a workspace. Such errors are now written
  to a crash log (`State/Crashes`, the newest 20 kept), shown in the Output and status bar, and the IDE keeps running.
  Only the runtime's own failures, such as running out of memory, still end it, after the session is saved.
- **Opening a workspace can't fail halfway.** Any failure while opening shows "Could not open" on the start screen. It
  used to leave a half-open IDE, or reach the dispatcher and close the app.
- **A double tap on a recent workspace opens it once.** Two taps opened it twice at the same time. The second closed the
  first mid-load, and the first's failure then closed the second.
- **F5 or Build pressed while Run checks a project's databases waits.** The checks take a few seconds per connection,
  and during them a second build and run could start beside the first.

### Hostile files and folders

- **A symbolic link back into the workspace is walked once.** A `self -> .` link made the project's sources repeat up
  to the system's 40-link limit (two such links meant 2^40 paths, a hang), filled Solution Explorer with copies that
  hid real files, and made project search follow it. Links that loop back are now detected by their real path, and
  every walk has a limit: 20,000 folders for sources, 128 levels for the tree.
- **Endless and huge files are refused, not read until memory runs out.** A link to `/dev/zero`, a log another program
  is still writing, or a project that imports `/dev/zero` passed the size check and was read without end. The editor,
  the project, solution and import readers and the C# source reader now stop at 16 MB.
- **Deleting a large folder doesn't freeze the IDE.** The trash is in TabStudio's own storage, so a folder in shared
  storage is copied there. That copy ran on the UI thread, and a `node_modules` folder froze the IDE until Android
  offered to close it. It now runs in the background, and links are copied as links rather than followed.

### The network

- **A Wi-Fi sign-in page no longer destroys the offline package index.** A captive portal answers with 200 and HTML.
  That page was written over Alpine's last good package index before it was checked, and was then deleted, so
  toolchains could not be installed offline either. The index is now verified before it replaces the old one, and the
  error suggests signing in to the network.
- **A server that never answers is given up on.** Toolchain downloads had a stall limit for the body but not for the
  headers, so a connection that was accepted and never answered held the install until the user cancelled it.
- **A stalled NuGet source no longer blocks every restore until restart.** The read of a source's service index had no
  time limit once its headers arrived. A stalled one stayed pending, and every later restore from that source waited
  on it.
- **CI logs and repository downloads fail cleanly.** A dropped connection now gives a GitHub error, where it used to
  close the app from the CI log panel, and a stalled one gives up after a minute instead of spinning for good.
- **The agent notices a dead connection.** A stream that goes quiet for 90 seconds (the API pings far more often) now
  ends with an error instead of waiting for Stop, and the client's own timeout no longer shows as "Stopped." as if the
  user had pressed it.

### Smoother and steadier

- **Typing in a large unsaved file no longer stutters.** Every two seconds of typing, the session saved every unsaved
  document as JSON on the UI thread. It is now written in the background, and an older save that finishes late can't
  replace a newer one.
- **Font size, language, SIM and color-mode changes no longer recreate the activity.** None of them changes what the
  IDE draws.

## Measured

The emulator self test now records startup, memory and the editor's frames on every run (`measurements.txt` in the
emulator job's logs). The same script ran on 0.20.3's code for comparison; the pull request that made this release has
both sets of numbers.

## Still to do

- The local AI model download (`ModelManager`) still starts from zero after a broken connection and has no stall limit.
  It should use the toolchain downloader, which resumes.
- Open VSX installs an extension without its signature when fetching the signature fails, rather than retrying.
- The debugger resolves stack frames on the UI thread, reading each frame's source file. Deep Kotlin stacks can make
  each step slow.
- The recording timeline's "jump to last write" changes debugger state from a background thread.
- Very long single lines (a minified 16 MB file) still open, and scrolling sideways through them is slow.

## Install

1. Download `TabStudio-0.20.6.apk` below on your tablet.
2. Open it and allow installing apps from your browser or file manager when Android asks.

Requires Android 9 or later on 64-bit or 32-bit ARM, with 3 GB of memory or more (2 GB with TabStudio Link). It installs
as an update over earlier 0.20 releases, and keeps their settings, recent workspaces and sessions.

## Verified

Every commit runs the unit tests of every library, headless UI tests of the real IDE in both themes, an APK build with
signature verification, and the full self test on an Android tablet emulator. This release adds tests for each failure
above, among them: a session restored while the app is sent to the background; a restore interrupted by the app
ending; a source tree with links back into itself; a link to `/dev/zero`; a captive portal in front of the package
mirror; a download server that never answers; a log stream that breaks; an agent stream that goes quiet; and a
workspace opened, edited and closed repeatedly with each closed IDE collected.
