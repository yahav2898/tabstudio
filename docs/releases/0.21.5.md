TabStudio 0.21.5 fixes thirteen problems found after 0.21.4: in the Windows Forms designer, the upgrade of .NET
Framework projects, Polyglot and Jupyter notebooks, file names with a colon, the port to Avalonia, containers, the
copy of unsaved text a crash keeps, and Android's display size and Bold text. It also adds what CI never checked: an
update from 0.19.0 through 0.21.1 that keeps settings, sessions and toolchains. Each fix has a regression test that
failed before it.

## Fixed

- **A new control's name never collides with the form's own code.** The designer checked a new name only against the
  other controls, so `button1` could be added to a form whose Form1.cs already had a `button1` field or method, which
  did not build (CS0102), and a control could be renamed `Text` or `Size`, hiding the form's own property. New names
  now skip every member the form's code file and designer file declare, in Visual Basic in any case, and a rename to
  one of them, or to a member the form inherits, is refused with a message that says why. A paste reads the form's
  files once for all the names it gives, not once per pasted control.
- **Comments and `#if` blocks in InitializeComponent are kept.** The designer wrote InitializeComponent again from
  its statements alone, so comments went, and the statements of an `#if DEBUG` … `#endif` block were written without
  it, for every build. A block of conditional compilation is now kept as it was written, with the statements inside
  it. A region changes nothing that is compiled, so the controls created inside one are designed as any others, and
  its `#region` and `#endregion` lines are kept as comments are, wherever they still pair up. A comment stays with its
  statement, before it or after it on its line, also when the statement's value changes; a comment whose statement
  went is kept at the end of the method. In C# and in Visual Basic. Reading the method takes time in proportion to its
  length, also for a form of thousands of statements.
- **An upgraded project no longer names analyzers in `..\packages\`.** Upgrading a .NET Framework project removed
  packages.config, so that folder is no longer restored, but kept its `Analyzer` items that pointed into it, and the
  build stopped on a missing analyzer. Those items now go: the package's PackageReference brings its analyzers, and
  an analyzer of a package packages.config did not list becomes a PackageReference of its own, with
  `PrivateAssets="all"`. A package folder is matched by the package's whole name and version, so `Foo` in
  packages.config does not take the place of `Foo.Analyzers.1.0.0`.
- **A Polyglot notebook (.dib) keeps its line endings and reads every kernel marker.** A file with Windows line
  endings was saved with `\n`, which rewrote every line of it; it now keeps `\r\n`. A marker with a trailing space or
  options after the kernel's name, such as `#!csharp ` or `#!fsharp --kernel-name fs`, now starts a cell, and is
  written back as it was.
- **A Jupyter notebook keeps the form of its JSON outputs and its cell ids.** An `application/json` output the file
  stored as a string came back as a JSON object when the notebook was saved; it stays a string. A notebook of format
  4.4 whose cells have ids, as some tools write, lost them on save; it keeps them.
- **Visual Basic forms with two controls in one declaration.** `Dim Button1, Button2 As Button` in a designer file was
  kept while the designer wrote a field for each control too, so both were declared twice. The shared declaration
  now goes, as it did in C#. A declaration shared with a field that is not a control's stays, and the designer writes
  no second one; renaming the control renames it in that declaration, in C# and in Visual Basic, so the file still
  builds.
- **File names with a colon.** On Android a colon is an ordinary character in a file's name, but TabStudio Live left
  such files out of a session, and an extension with one, such as `icons/file:dark.svg`, could not be installed. Only
  a drive (`C:`) is refused now, and on Windows any colon, where it names an alternate data stream.
- **The port to Avalonia escapes resource names for MSBuild.** A resource named `a;b.png` became two items, and
  `100%.png` an escape MSBuild could not read. `%`, `;`, `$`, `@`, `'`, `*` and `?` are now escaped in the project file.
- **A Compose service with only `build:` runs.** A service built from a Dockerfile, with no `image:`, could not be
  started. TabStudio now builds it: stages and `--target`, `ARG`, `ENV`, `WORKDIR`, `USER`, `COPY` and `ADD` with
  `.dockerignore`, `--from` and `--chmod`, and `RUN` under PRoot, each step a layer. The build is skipped while the
  Dockerfile, its arguments and the context's files are unchanged. With both `build:` and `image:`, the image is pulled
  and built only when the pull fails. As in Docker, `COPY` and `ADD` follow a link in the build context only inside
  it, so a link in a repository cannot copy a file from outside, such as TabStudio's own tokens and keys, into an
  image.
- **Containers share their image's programs and libraries where the system allows it.** Every container was a full
  copy of its image. On a system that lets apps make hard links, the large program and library files of `/bin`,
  `/lib` and `/usr` are now shared with the image and made read-only; a container replaces them, as package managers
  do, rather than writing them in place. The image keeps its own modes for them, so a build from it, or `COPY --from`
  it, gets the same file modes whether or not a container shares them. Android does not let apps make hard links, so
  on a tablet containers are still full copies (see Known issues).
- **The F5 app's settings find a container by its `container_name` or a network alias.** A setting such as
  `DB_HOST=my-postgres` that named a service's `container_name`, or one of its aliases, was left as it was, so the app
  could not reach the database. It is rewritten to `127.0.0.1` and the service's port, as a service's own name is, and
  F5 starts that service.
- **A crash on a background thread keeps the text typed a moment before.** The editor's text can be read only on the
  UI thread, and a crash on another thread ends the app before that thread runs again, so the session saved then was
  the last throttled one, up to two seconds of typing earlier. Every change now keeps a snapshot of the document's
  text, which costs no copy of it, and the crash saves the session from those.
- **Changing the display size or Bold text no longer restarts the IDE.** DeX's and Android's display size (density)
  and Android 12's Bold text (font weight) were not among the changes the IDE's activity handles itself, so Android
  recreated it and threw away its window. CI now checks the APK's manifest for them, reading aapt2's whole output so
  that the check cannot fail a good APK.

## Checked in CI

- **An update from 0.19.0 through 0.21.1.** For each of the eleven releases from 0.19.0 to 0.21.1, a test lays out the
  app's data as that release left it, in that release's own formats, and starts this one on it: the settings, the
  session with its unsaved text, breakpoints and watches, and the installed toolchains are all read and kept, and no
  file is reset.
- **Every release is published.** A merge to main soon after a release no longer cancels that release's run.
  - Each commit to main gets its own CI run, and only the highest version is marked latest.
  - An error from GitHub while publishing is retried.

## Known issues

- On Android, containers still copy their image's files, since apps cannot make hard links there; sharing them on
  the tablet needs copy-on-write in TabStudio's PRoot.
- A startup project chosen in 0.21.1 or earlier is not restored after the update, because those sessions did not say
  whether it was chosen or picked automatically.

## Install

1. Download `TabStudio-0.21.5.apk` below on your tablet.
2. Open it and allow installing apps from your browser or file manager when Android asks.

Requires Android 9 or later on 64-bit or 32-bit ARM, with 3 GB of memory or more (2 GB with TabStudio Link). It installs
as an update over earlier releases, from 0.19.0 on, and keeps their settings, sessions and toolchains.
