TabStudio 0.21.1 fixes what broke where 0.21.0's features meet: containers with the debugger, Services with the
Database Explorer, the .NET work with Hot Reload and Test Explorer, and Android's foreground service under load. It
also makes CI's flaky checks steady, so a green commit is green on its first run.

## Fixed

- **F5 runs programs that call `Environment.Exit`.** Ctrl+F5 ran them, but F5 refused them with TS1001. The debugged
  program now ends with its exit code, as it does without the debugger.
- **A library's `Environment.Exit` no longer closes TabStudio.** Every project an in-process program loads is built
  so that an exit ends the program, not only the project that starts it.
- **xUnit v3 theories run.** Every `[Theory]` in an xUnit v3 project said "No data found", because v3's data
  attributes have new base types. `[InlineData]`, `[MemberData]`, `[ClassData]` and custom v3 data attributes work.
- **Hot Reload on Save applies Visual Basic edits.** It looked only at `.cs` files.
- **Database credentials keep their values.** A service named `postgres` with `POSTGRES_USER`, `POSTGRES_PASSWORD`
  and `POSTGRES_DB` set to `postgres` had all three turned into `127.0.0.1`, in the app and in the database itself, so
  the Database Explorer could not sign in. A value that is only a service's name is treated as a host only in a host
  setting such as `DB_HOST`.
- **An app with no `depends_on` gets its database on F5.** Services now starts what the app's own environment points
  at, such as `DATABASE_URL=postgres://…@db/app`.
- **A failed or cancelled image pull ends its operation.** A pull of `postgres` kept TabStudio's foreground service
  and its notification running until Android stopped the app.
- **Image layers cannot copy TabStudio's files into a container.** A hard link to a link pointing outside the image
  is resolved inside the image, as the container sees it.
- **MySQL 8.4 containers start.** Creating a container from an image that contains a FIFO, such as `mysql:8.4`,
  never finished: the copy opened the FIFO and waited for a writer. FIFOs are now recreated, not read.
- **TalkBack names the Containers view's tabs.**
- **TabStudio no longer ends during back-to-back installs.** The service that keeps long operations running started
  with a ten-second deadline that Android enforces with an "App not responding" ending; when one install ended just as
  the next began, Android ended TabStudio. It now starts without that deadline.
- **The Capacitor template installs the same packages every time.** It ships a `package-lock.json` and installs with
  `npm ci`; a dependency published minutes earlier could fail a new project's first install.

## CI

- The native emulator shard ran 540 to 886 seconds of its 900; C/C++ and Java moved to a new `compiled` shard.
- The containers workflow runs on `main` and agent branches when container code changes; before, `main` never ran
  it. A new compatibility job starts common database, cache, queue, web server and runtime images on x64 and ARM64.
- The compatibility job gives each image a deadline and names the step an image that never returns was in, so one
  image cannot hold the job until its time limit.
- A test's own quoted compiler errors no longer count as a build failure in the retry policy.

## Install

1. Download `TabStudio-0.21.1.apk` below on your tablet.
2. Open it and allow installing apps from your browser or file manager when Android asks.

Requires Android 9 or later on 64-bit or 32-bit ARM, with 3 GB of memory or more (2 GB with TabStudio Link). It installs
as an update over 0.21.0.

## Verified

Every commit runs the unit tests of every library, headless UI tests of the real IDE in both themes, an APK build with
signature verification, and the self test on an Android tablet emulator in five shards (managed, UI, native, compiled
and containers), each passing on its first attempt. The containers job pulls and runs real images on ARM64 and x64,
and the compatibility job records which common images start under PRoot; the [containers guide](../features/containers.md#image-compatibility) lists the results:
25 of 26 common images work on both architectures, including PostgreSQL, MySQL, MariaDB, MongoDB, Redis, Valkey,
RabbitMQ, Kafka, NATS, nginx, Caddy and the Node, Python, Go, Java, PHP, Ruby and .NET runtimes. `minio/minio` could
not be pulled because Docker Hub now requires signing in for it.
