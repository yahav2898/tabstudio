TabStudio 0.21.13 is a pass over the path from New Project, or an opened repository, to running, debugging and
testing it, in every language TabStudio supports. Test Explorer debugs tests, every debugger takes the same hit
counts, the C# debugger lists the program's threads, F5 debugs ASP.NET Core apps, Restart builds again, a build can
be cancelled, and New Project gains xUnit, NUnit and MSTest test projects. CI now creates, builds, runs and debugs
every template and runs the same debugger checks for every language with a debug adapter.

## New

- **Debug Tests.** Test Explorer's **Debug** (a row's menu, **Test > Debug All Tests**, **Debug Selected Tests**, and
  **Ctrl+R, Ctrl+A** and **Ctrl+R, Ctrl+T** as in Visual Studio) runs tests under the debugger: breakpoints in the
  tests and in the code they call stop, with stepping, Locals, Watch, the Call Stack and the exception helper, and the
  results land in Test Explorer as they do for a run. C# and Visual Basic tests on xUnit, NUnit and MSTest are built
  for debugging, as F5 builds a program, and run without the per-test timeout, so a test can stay paused while you
  look at it; an assertion that fails pauses where it left the test, as Visual Studio pauses at an exception
  unhandled by user code. pytest runs under debugpy, Vitest, Jest, Mocha and `node --test` under js-debug (Jest in
  one process), PHPUnit and Pest under Xdebug, and a Go package's tests under Delve, from a test binary built without
  optimizations. Cargo, JUnit (Gradle and Maven), Swift and Dart tests still run without the debugger, and say so.
- **Unit test projects in New Project.** **xUnit Test Project**, **NUnit Test Project** and **MSTest Test Project**,
  as Visual Studio writes them, with the test SDK and adapters `dotnet test` needs, so the same project runs on a
  computer and in CI.
- **F5 debugs web apps.** ASP.NET Core apps and Blazor Web Apps, including the Web, Razor Pages and MVC templates,
  are served from their debug build in a debug session: a request that reaches a breakpoint in an endpoint, a page, a
  controller or a service stops there while the web preview waits, and an exception that leaves the app's code pauses
  with the exception helper. Saving restarts the app with a new debug build, Shift+F5 stops it and Ctrl+Shift+F5
  debugs it again. Before, F5 served them without the debugger.
- **Hit counts for every debugger.** C# and Visual Basic breakpoints get **Hit Count...** in the breakpoint menu, as
  debug adapters' did: stop on the fifth hit only (`5` or `= 5`), on the fifth and after (`>= 5`), or on every fifth
  (`% 5`); with a condition, only the hits where it holds count. The IDE counts the hits of debug adapters' breakpoints
  itself, so a hit count means the same in Python, JavaScript, Go, Rust, C and C++, Java, Kotlin, PHP and Swift: a
  bare number stopped once in one adapter and on every later hit in another, and LLDB ignored `>= 5`. A hit count
  that is not one is refused with the forms it can take.
- **Threads in the C# debugger.** When a C# or Visual Basic program pauses, the Call Stack lists its threads in its
  own code, each stopped at its next statement, and choosing one shows its frames, as debug adapters' threads did.

## Fixed

- **Restart debugs the code as it is now.** Ctrl+Shift+F5 in a Go, Rust, C or C++, Java, Kotlin or Swift project
  launched the last build again: an edit made while debugging was not in the restarted program. Restart now saves
  and builds again, as F5 does.
- **A build can be cancelled.** Shift+F5 and the build's Cancel in the operations list stop a C# or Visual Basic
  build before its next project, and the project being compiled where the compiler checks; the Output panel says
  `Build: cancelled`. Before, nothing could stop a long build.
- **The exception helper for every adapter.** A debug adapter that stops at an exception without answering
  `exceptionInfo`, as Xdebug's does, showed no exception helper; the stop's own description is now shown.
- **A program stopped outside its source shows the code that led there.** An uncaught C++ exception, a signal or a
  crash in a library stopped in frames with no source here (the C library's `abort`), so the editor showed nothing.
  The first frame with source is now the current one, with the exception helper on its line.

## CI

- A **New Project templates** job creates every .NET template, restores it from nuget.org, builds it with no
  errors and no warnings, runs it and stops it at a breakpoint, and for the test projects runs and debugs their tests.
  A test lists every template with the tests that check it, so a template added without them fails CI.
- The same debugger checks run for Python, Node.js, Go, Rust, C++, Java, Kotlin, PHP and Swift with their real
  adapters, on programs made from their templates: a conditional breakpoint, Step Into, Over and Out, a hit count, the
  threads, an uncaught exception, Stop, and Restart after an edit. Test Explorer's Debug runs with pytest,
  `node --test`, `go test` and PHPUnit. The Kotlin script and PHP web site templates got their first tests.
- A third real-repositories job runs the tests of twelve pinned .NET libraries on xUnit, NUnit and MSTest with
  Test Explorer's Run All after their builds.

## Install

1. Download `TabStudio-0.21.13.apk` below on your tablet.
2. Open it and allow installing apps from your browser or file manager when Android asks.

Requires Android 9 or later on 64-bit or 32-bit ARM, with 3 GB of memory or more (2 GB with TabStudio Link). It installs
as an update over earlier 0.21 releases.

## Verified

Every fix has a regression test that failed before it: hit counts in the C# debugger's engine and in the IDE's
breakpoint menu, with a condition and without; a hosted debug session stopping, stepping and cancelling the code its
caller runs; debugging an xUnit test into its library and through its failed assertion, and stopping a debugged run;
Test Explorer's Debug commands; a request to the web template stopping at a breakpoint in its endpoint; a build
cancelled with Stop; the threads of a paused C# program; the debug plans of pytest, Go, the Node.js runners and
PHPUnit; and, with real adapters, the debugger checks and Debug Tests of each language above.
