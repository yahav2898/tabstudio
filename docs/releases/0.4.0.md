TabStudio 0.4 brings GitHub into the IDE: review and merge pull requests, see your commit's CI live in the status bar, read GitHub Actions runs and their logs, and fix CI's errors with Claude.

## What's new in 0.4

- **Pull request review.**
  - The Pull Requests window (side bar, View or Git menu) lists open pull requests, yours, those waiting for your review, and closed ones.
  - A pull request opens as a page: its description, reviewers, conversation, changed files and commits.
  - In a file's diff, conversations sit under their lines with Reply and Resolve. Tap the margin, or select lines and press Ctrl+Shift+Enter, to comment; comments wait in a pending review until **Finish Review** sends it as a comment, an approval or a request for changes.
  - **Merge** with the repository's merge, squash or rebase method, edit the message, and delete the branch. Drafts get **Ready for Review**.
  - **Check Out** switches the workspace to the pull request's branch, so F5 and Test Explorer run its code; there, the editor shows its conversations beside their lines.
  - **Review with Claude** drafts review comments on the diff with your API key; keep, edit or dismiss each one before anything is posted.

- **CI in the status bar.** When a workspace came from GitHub, its commit's checks show next to the branch: a spinner with "2/5" while they run, then a red "1 failed" or a green "Passed". The tooltip lists every check. Committing, pushing, pulling or switching branches follows the new commit at once.
- **A GitHub Actions window**, from the status bar, the side bar's Actions tab, or the View and Git menus.
  - **This commit:** its check runs and commit statuses.
  - **Runs:** the branch's runs, filtered by branch and workflow; pull down to refresh.
  - **Run details:** the jobs and their steps, with Re-run all jobs, Re-run failed jobs, Cancel and Open on GitHub.
  - **Run workflow:** a form built from the workflow's `workflow_dispatch` inputs (text, choice, boolean, number and environment), with a branch picker.
- **Job logs you can read.** A job or step opens its log in a read-only tab, folded by step and `##[group]`, with failed steps open and the caret at the first error. Errors are red, warnings amber, and the log's own colours are kept. F8 and Shift+F8 move between errors; timestamps show on demand. Very large logs open as their beginning and end, with "Show the full log" one tap away.
- **CI errors in the Error List.** A **CI** filter shows what failed on GitHub beside your local errors, each with the check that reported it. Tap one to go to the line, or **Fix with Agent**, which is told the check and the commit. They are replaced by the next failing commit and cleared when it passes.
- **Watched repositories.** Add any repository by name or address and see its latest run on the default branch.
- **Notifications.** When a run finishes, a notice in the IDE opens it, and on Android a system notification can too.
- **Touch buttons that fold away.** The floating editing and debug buttons fold into one small button at the editor's edge, so they cover no code; one tap brings them back.

## Fixed

- Claude's answers in the agent panel stay one message, never split mid-word.
- Closing a workspace no longer leaves a session save waiting to run against it.

## Token permissions

- **Fine-grained token:** **Pull requests** (read and write), **Contents** (read and write, for merging, deleting branches and checking out), **Actions** (read, or read and write to re-run, cancel and start workflows), **Checks** (read), **Commit statuses** (read) and **Metadata** (read).
- **Classic token:** `repo` (or `public_repo` for public repositories only).
- **Signed out,** public repositories show their checks and runs. Reading job logs, reviewing and merging need a sign-in.

## Install

1. Download `TabStudio-0.4.0.apk` below on your tablet.
2. Open it and allow installing apps from your browser or file manager when Android asks.

Requires Android 9 or later on 64-bit or 32-bit ARM, with 3 GB of memory or more. It installs as an update over 0.3.

## Verified

Every commit runs these checks in CI:

- the unit tests of every library, including builds against real packages from nuget.org, and GitHub's API scripted as GitHub answers it;
- headless UI tests that type, tap and press keys in the real IDE, with screenshots;
- an APK build with signature verification;
- the app on an Android tablet emulator. There it runs the sample and answers its question, debugs it to a breakpoint, serves a new ASP.NET Core app and asks it for its page, shows a new Avalonia app and taps its button, and previews the app's view in the XAML designer.

This release was published by CI only after its own build passed all of them.
