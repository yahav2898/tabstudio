TabStudio 0.16 builds real-world .NET repositories as the .NET SDK does, runs the backing services a repository's Compose file describes natively on the tablet, and adds experimental Flutter and Dart.

## What's new in 0.16

- **Real-world repository compatibility.** Projects compile against the projects their references reference, as the SDK passes them, honoring `ReferenceOutputAssembly`, `OutputItemType="Analyzer"`, `PrivateAssets="all"` and `DisableTransitiveProjectReferences`. The SDK's generated assembly attributes are there (`AssemblyAttribute` and `InternalsVisibleTo` items with their public keys), and strong-named projects are signed with their key files, so friend assemblies see internals. Source generators find dependencies in other folders of their package, and a generator that cannot load or that fails is shown in the Error List. TabStudio now follows `<Import>`s of `Directory.Build.props`, `Directory.Build.targets` and projects, reads `Directory.Packages.props` properties, expands package versions given as properties and `$(MSBuildThisFileDirectory)`, and evaluates simple item conditions. A package's analyzers stay with the projects that reference it, as with NuGet. Build Solution builds in dependency order and reports each error once. MediatR and ardalis/CleanArchitecture build with no errors, as in Visual Studio.
- **Aspire AppHosts, honestly.** The Compatibility Doctor explains that an Aspire AppHost runs on a computer, where Aspire's developer control plane starts the app's projects and containers. It is never chosen as the startup project, and Build lists it as skipped with that reason instead of reporting its generated code as errors.
- **Backing services without Docker.** **View > Services** reads `compose.yaml` and Dev Container Compose references, and runs PostgreSQL, Redis/Valkey, MariaDB for MySQL, RabbitMQ, nginx, Mailpit, MinIO and MongoDB (when Alpine packages it) as native PRoot processes, with start, stop, restart, health, logs and preview links. F5 starts the startup project's dependencies first and points its connection strings at localhost. Each workspace keeps its own data; PostgreSQL runs its init scripts once, and image versions are matched against the signed Alpine index. It is a native development runner, not Docker emulation; see [Services](../SERVICES.md).
- **Flutter and Dart (experimental).** The Flutter Toolchain Store entry installs Flutter and its Dart SDK in a separate Ubuntu glibc PRoot environment. `pubspec.yaml` projects get **flutter pub get**, Dart IntelliSense through the analysis server and Dart console debugging; the counter templates run in the web preview, and saving hot-restarts Flutter web. Native Android deployment of Flutter apps is not verified yet; see [Flutter](../flutter.md).

## Fixed

- A program in the Linux environment no longer loses its working directory when another one exits, such as a language server stopping as a workspace closes: PRoot's mount points in the shared root file system, including services' data folders, are now created once by the IDE, so no single PRoot process removes them. Cargo runs are named after their crate in the Output panel.
- A build replaces live-analysis errors of the projects it built, so errors reported before a project's generators loaded no longer stay in the Error List.
- ASP.NET Core 10's generator that makes a top-level `Program` public now runs only for projects targeting .NET 10, as the SDK chooses generators by target framework.
- The IDE test job's time limit now holds its single retry.

## Install

1. Download `TabStudio-0.16.0.apk` below on your tablet.
2. Open the APK and allow installing apps from your browser or file manager when Android asks.
3. Install optional toolchains from **Tools > Toolchain Store**. The first package, SDK, service and model downloads need an internet connection. Keep Android System WebView up to date for web previews.

Requires Android 9 or later on 64-bit or 32-bit ARM, with 3 GB of memory or more (2 GB with TabStudio Link). Flutter needs a 64-bit build. It installs as an update over 0.15.

## Verified

The integration pipeline runs every library, the real IDE in both themes, APK signature verification, every Android emulator shard, Windows Bridge on Windows, and the dedicated SSH, mobile, local-inference, services and Microchip PIC jobs. The new **Real repositories** job opens ten public repositories pinned to commits (GuardClauses, MediatR, CleanArchitecture, FluentValidation, AutoMapper, Serilog, eShopOnWeb, Polly, Humanizer and BlazingPizza) in the IDE, builds them, and holds each to an error baseline that may only go down. The integration PR records the checked SHA and CI results.
