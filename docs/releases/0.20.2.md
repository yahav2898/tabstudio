TabStudio 0.20.2 fixes seven of the ten problems the 0.20.1 quality pass ranked as hurting users most. Edits typed
while Git pulls or switches branches are never lost, installs and builds finish while TabStudio is in the
background, typing stays smooth in long files, cross-project edits and memory pressure no longer freeze 3 GB
tablets, any public repository opens without signing in, PostgreSQL tables with json, xml, point, enum and date
columns can be edited, and documentation folders are no longer mistaken for projects.

## Fixed

### Never losing work

- **Edits typed while a pull, a branch switch or a pull-request checkout runs are kept.** The editors stay editable
  while the operation talks to GitHub, but afterwards each open file was replaced with what it wrote, and anything
  typed meanwhile was gone. Now TabStudio reads every open file before the operation starts and, for a document
  edited since, merges the edits into the new file with the same three-way merge a pull uses. Where your edits and
  the new file changed the same lines, both are kept between `<<<<<<< Yours` and `>>>>>>> GitHub` markers and the
  status bar says so. Such a document stays unsaved, and one Undo goes back to exactly what is on disk. A file the
  new branch does not have stays open with your edits instead of closing.

### Background work

- **Long operations finish while TabStudio is in the background.** Android freezes an app soon after you switch
  away unless it runs a foreground service, so a toolchain install, a build, project setup or a NuGet restore
  stopped where it was until you came back. While any of them runs, TabStudio now keeps a foreground service with
  a partial wake lock, and its notification shows the newest operation and its progress (tap it to open the
  operations panel). When an operation ends in the background, a notification says how. Analysis, which only the
  open IDE needs, does not keep TabStudio running. The service needs no new prompt; on Android 13 and later its
  notification shows in the shade once you allow TabStudio's notifications.

### Performance

- **Typing stays smooth in long C# files.** Every keystroke copied all of the file's color ranges to move them past
  the edit: about 0.6 MB of large-object allocation per keystroke in a 2,500-line file, and over 1 GB for a Format
  Document. The ranges now move in place.

  | 2,509-line file, 10,632 ranges from Roslyn | Before | After |
  | --- | --- | --- |
  | Moving the colors through a keystroke | 332 KB and 121 µs | 0 KB and 21 µs |
  | Moving them through a Format Document (2,000 edits) | 649 MB and 311 ms | 0 MB and 19 ms |

  Measured in CI by `EditorTypingBenchmarkTests` in the real editor, with the old and new code on the same ranges and
  the same edits (`editor-typing-csharp.md` beside the IDE job's screenshots).
- **Cross-project edits and memory pressure no longer freeze 3 GB tablets.** On a compact tablet, projects nobody
  has open are seen through metadata-only images. An edit to such a project (Rename across projects does that) and
  every memory-pressure callback reloaded the whole solution and compiled the image on the UI thread, and a reload
  started elsewhere held the lock every keystroke waits for. The image is now compiled on a background thread from
  an immutable snapshot, and the solution is rebuilt from texts and images when it is ready, in milliseconds; the
  garbage collection after memory pressure runs there too. On an app and a 300-class library seen as an image
  (`SkeletonReloadMeasurementTests`, in CI's `skeleton-reloads.md`):

  | | The calling thread waited, before | After | Longest keystroke wait meanwhile |
  | --- | --- | --- | --- |
  | Rename edits the library | 942 ms | 2.8 ms | 9 ms |
  | Memory pressure | 20 ms | 0.1 ms | 9 ms |

  "Before" is the reload and image compile the caller used to do itself, timed on the same solution; a real
  solution has more projects and a 3 GB tablet is several times slower than CI.
- **Unsaved edits survive a skeleton reload.** The reload built its second solution from the first one's texts,
  which load lazily, so a file of the open project that nothing had read yet took its text from the disk until the
  next keystroke sent it again.

### GitHub and databases

- **Open from GitHub works for any public repository without signing in.** Files a repository's archive leaves out
  (`export-ignore`) were downloaded with one API request each, and signed out GitHub answers 60 requests an hour:
  symfony/console needed 427 and laravel/framework 1551, so opening them failed. Signed out, those files now come
  from `raw.githubusercontent.com`, which does not count against that limit, checked against their Git hashes; only
  a mismatch falls back to the API. Pulls benefit the same way.
- **PostgreSQL tables with json, jsonb, xml, point or enum columns can be edited, and empty dates filled.** Values
  were sent as text, which PostgreSQL does not turn into those types by itself, and json, xml and point have no `=`
  operator for the check that the row did not change. Each value is now cast to the column's own type, as
  PostgreSQL parses a literal, and those columns are compared by their text.

### Projects

- **docs/ and wwwroot folders are no longer projects.** A Sphinx documentation folder became a C/C++ project from its
  Makefile and a Python project from its `conf.py`, a docs site's `package.json` started `npm ci` in project setup,
  and a web app's `wwwroot` libraries became Node.js projects. Below the workspace folder, `docs`, `doc`,
  `documentation` and `wwwroot` are no longer searched for projects (opened on their own, they still are), and a
  Makefile that runs `$(SPHINXBUILD)`, MkDocs, Jekyll, Hugo or Doxygen is not a C/C++ program.

## Install

1. Download `TabStudio-0.20.2.apk` below on your tablet.
2. Open it and allow installing apps from your browser or file manager when Android asks.

Requires Android 9 or later on 64-bit or 32-bit ARM, with 3 GB of memory or more (2 GB with TabStudio Link). It installs
as an update over 0.20.1.

## Verified

Every commit runs the unit tests of every library (with PostgreSQL 17 for the database tests), headless UI tests of
the real IDE in both themes, the real-repository job, an APK build with signature verification, and the full self
test on an Android tablet emulator in three shards, which runs toolchain installs and builds under the new
foreground service. Each fix above came with a test that failed before it.
