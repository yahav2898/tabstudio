TabStudio 0.21.12 is a pass over every command a person can reach in the IDE, on a real solution, as a tablet is
used: every menu command and Ctrl+Q entry, every key gesture the IDE shows, every button of the shell and its tool
windows tapped with a finger, every context menu item and the Start window's buttons, in landscape and portrait, in the
dark and the light theme, with touch and with a hardware keyboard. It also covers what only a tablet does: split
screen and pop-up windows, rotation, going to the background in the middle of a build or a debug session, a keyboard
attached and taken away, the on-screen keyboard over the caret, and Hebrew and IME composition in the editor, in Find
and Replace and in the Terminal. What the pass found is fixed, each with a test, and CI now runs every command on
every commit.

## Fixed

- **The on-screen keyboard no longer hides the line you type on.** When it opened on a landscape tablet, the bottom
  panel kept its 200 pixels and the editor was left a line or two, often not the caret's. The bottom panel now takes
  at most half of a short editor area (40% in portrait, as before), and the editor scrolls a caret that was in view
  back into view when the keyboard, a split screen or rotation makes it shorter.
- **Escape closes every dialog.** TabStudio Link, Join a Swarm, Share Session, Join Live Session, Add a device and the
  GitHub account answered only a tap. Escape now closes the dialog on top, as its Close, Cancel or Done button does,
  also when nothing has the keyboard focus, as after a tap.
- **A confirmation answers the keyboard.** A dialog that asks to confirm, with no box to type in, had no focus: Enter
  and Escape did nothing and keys typed into the editor behind it. Its button now takes the focus, Enter confirms and
  Escape cancels wherever the focus was, and the focus goes back where it was, such as the editor after Rename.
- **View > Solution Explorer and Ctrl+Alt+L show Solution Explorer.** They folded the side bar away instead, leaving
  Git Changes or whatever was on it. Folding the side bar is **View > Side Bar**. **Sync with Active Document** also
  shows Solution Explorer, where it used to select the file out of sight.
- **Only the chosen tool window is on the side bar.** Solution Explorer and Properties stayed under the others, where
  Tab, F6 and TalkBack still reached their controls.
- **Navigate Backward and Forward are available only when they go somewhere.** The toolbar's arrows looked tappable
  with nowhere to go, and Back could "go" to the document already shown.
- **Select All, Cut, Copy and Paste by touch.** Without a keyboard nothing selected a whole file. The editor's context
  menu has **Select All**, and the Edit menu has **Cut**, **Copy**, **Paste** and **Select All**.
- **Go To Line (Ctrl+G).** Edit > Go To Line asks for a line and moves the caret there, and a tap on the caret's place
  in the status bar does the same; it was a button that did nothing.
- **The status bar's labels are labels.** The indentation, encoding, line endings, language and device took taps and
  the keyboard's focus and did nothing; in More they were items that ran nothing.
- **Find's toggles are whole touch targets.** Match case, Whole word and Regular expression were 22 by 20 pixels.
- **Fitting small windows.** In a third of a split screen or a pop-up window, the Error List kept no room for a single
  row, the References summary ran off the edge, Device Peripherals cut its field header in half and left its fields
  no room, and the Terminal's keys were narrower than a phone-sized window's touch target.
- **The dialog's text box has a name.** TalkBack read the prompt's box, in Rename, Go To Line and the others, as an
  unnamed edit box; it now reads the dialog's title.
- **A keyboard's Home, End, Page Up and Page Down count as a keyboard.** The touch bar stayed over the code when one of
  them was the first key pressed.
- **Stop Debugging is a stop, not a crash.** About half the time, stopping a debug session printed "Unhandled
  exception. DebugSessionStoppedException" in red in the Output: the debugger's own way of ending the program was
  reported as the program's crash.
- **Closing a solution while the editor still waits on the language service** cancels those requests, where they
  failed with an error nothing was waiting for.

## CI

A new job, **Every command**, runs the sweep (tests/TabStudio.App.Tests/Sweep) in the dark and the light theme. It
fails on any exception, error written to the Output, UI thread blocked for more than 2.5 seconds, dialog that Escape or
a tap cannot close, command or button that changes nothing a person can see, and screen that breaks the accessibility
and layout rules (touch targets, names, contrast, clipped text, controls off the screen or over each other), except
what `SweepAllowances.cs` lists with its reason. Its reports, with a picture of each finding, are `sweep/` beside the
screenshots. Publishing a release now waits for it.

## Install

1. Download `TabStudio-0.21.12.apk` below on your tablet.
2. Open it and allow installing apps from your browser or file manager when Android asks.

Requires Android 9 or later on 64-bit or 32-bit ARM, with 3 GB of memory or more (2 GB with TabStudio Link). It installs
as an update over earlier 0.21 releases.

## Verified

Every fix has a test that failed before it, in tests/TabStudio.App.Tests/Sweep/CommandFixTests.cs, and the sweep
itself: about 180 menu commands, 70 key gestures, 300 taps in two orientations, the context menus, the Start window and
150 tool window and dialog states on six screen and window sizes, in both themes.
