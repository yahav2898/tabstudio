TabStudio 0.21.3 is about the first hour after a project opens: what a developer does before writing anything new,
done on real public repositories pinned to commits. It adds Find in Files, makes a folder Git cloned on a computer
work with Git Changes as one downloaded in TabStudio, and has CI check on every commit that the editor's squiggles say
what the compiler says.

## New

- **Find in Files (Ctrl+Shift+F).** **Edit > Find in Files** lists every line of the solution's folder that holds some
  text, grouped by file in the References panel, with the word at the caret filled in. Letter case is ignored, as in
  Visual Studio. Open documents are searched as they are in the editor, saved or not; build output, dependencies,
  hidden folders, binary files and files over 4 MB are skipped, as the Solution Explorer skips them. Tapping a match
  opens it. Before, the only way to find text across files was the terminal.

## Fixed

- **A folder Git cloned from GitHub is linked when it opens.** A repository cloned with `git clone` on a computer and
  copied to the tablet, or cloned in the Terminal, opened with Git Changes offering to *publish it to GitHub as a new
  repository*. TabStudio now reads the clone's `.git` files (its branch, its commit, and the GitHub repository its
  remote names, from `https`, `ssh` and `git@` addresses, packed refs and worktrees included) and links the folder to
  that repository without downloading it again, so its changes, commits, pulls and branches work at once. A commit
  GitHub does not have is compared with the branch on GitHub; a branch GitHub does not have is linked as a commit, so a
  commit from the tablet never lands on another branch. `.tabstudio` is added to the clone's `info/exclude`, so Git on
  a computer leaves it alone. A private repository links once you sign in.
- **Build Solution says why a project was not compiled.** When a project's reference had errors, the project was
  counted as failed with no line of its own in the Output: in moq, ten of eleven projects failed with nothing under
  their "Build started" line. It now says which referenced project has the errors, as Visual Studio does.
- **Go to Definition with no file open** said "Open a C# file first." in Python, Go and every other language. It now
  says to open a code file.

## CI

- **Squiggles match the compiler on real repositories.** After each .NET repository of the real-repositories jobs
  builds, the job opens the first source files of every project (up to 24 per repository), analyzes them as the editor
  does, and fails when the editor shows an error the build does not or misses one it reports. 1,200 files of 58
  repositories agree; projects a build does not compile because a reference has errors are left out.
- **Test Explorer on real .NET repositories.** A .NET entry of `build/ci/real-repos.json` can name how many tests
  Test Explorer's Run All must pass after the build, as Python, Go, Rust and the other languages' entries already do.
- **Four more real repositories:** SmartEnum and ErrorOr (built, with their tests run in Test Explorer), Respawn, and
  itsdangerous (set up with its Python, tests in Test Explorer). Each .NET one builds with no errors.

## Install

1. Download `TabStudio-0.21.3.apk` below on your tablet.
2. Open it and allow installing apps from your browser or file manager when Android asks.

Requires Android 9 or later on 64-bit or 32-bit ARM, with 3 GB of memory or more (2 GB with TabStudio Link). It installs
as an update over the earlier 0.21 releases.

## Verified

Every commit runs the unit tests of every library, headless UI tests of the real IDE in both themes, an APK build with
signature verification, the self test on an Android tablet emulator in five shards, and the real-repositories jobs,
which now also compare the editor's errors with the build's in every .NET repository they open.
