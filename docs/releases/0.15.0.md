TabStudio 0.15 sets repositories up when they open, adds database and remote workspaces, and applies or inspects C# changes while a program runs.

## What's new in 0.15

- **Repository setup and static web sites.** Opening a Python or Node.js repository installs its toolchain and project packages, with progress, cancellation and a manifest-based cache. The setting is on by default and available through Ctrl+Q. Monorepo projects keep their own run targets. Folders with `index.html` run in the web preview; saving reloads HTML or replaces CSS without losing page state. HTML, CSS and JSON gain language-server completion and diagnostics.
- **Port to Avalonia.** Convert C# WPF and Windows Forms projects from the Compatibility Doctor, Project menu or Solution Explorer. The result is a sibling project; the original stays unchanged. A summary links structured port notes to source lines, stages them as one agent task of proposed changes, and offers undo. F5 runs the converted project in the native app preview.
- **Database Explorer.** Connect to SQLite, PostgreSQL and SQL Server, or discover connections in the solution's settings and user secrets. Browse schemas, tables, views, columns, keys and indexes. SQL tabs offer schema completion, Ctrl+Enter execution, cancellation, multiple result sets and CSV/JSON copying. Edit paged table data, inspect EF Core contexts and migrations, add a migration or update the database. Android encrypts saved connection credentials with its Keystore.
- **Remote development over SSH.** Import SSH config or add a host in Remote Explorer. Open SFTP folders with a source cache, edit and search files, use a remote terminal, and run build commands with linked diagnostics. Conflicting saves preserve local edits. Forward remote web ports into the preview. Publish ASP.NET Core through a local `dotnet publish`, SFTP upload and an existing systemd service, with rollback if activation fails. Android identities use non-exportable Keystore keys and server fingerprints are pinned.
- **Mobile and web-server workflows.** Local listening ports offer **Open in preview** and **Open in browser** for programs in any language. The Android SDK Store entry supplies Java, Gradle and Android tools, including ARM64 replacements; Kotlin Android and Capacitor templates build on the tablet and use Android's installation confirmation. A Logcat panel follows the installed debug app. Generated iOS workflows build on macOS through GitHub Actions; signed IPA/TestFlight distribution needs the owner's Apple credentials and repository secrets.
- **C# Hot Reload and Edit and Continue on desktop.** In the desktop host, apply edits with the toolbar or Alt+F10, optionally on save; Continue applies edits before resuming a breakpoint. Local Debug console, Avalonia, ASP.NET Core and server-side Blazor apps use Roslyn deltas and the runtime's metadata updater while preserving static state. Avalonia refreshes its content and hosted frameworks clear update caches. Compile errors keep the old code running; unsupported edits offer a restart. Android keeps the IDE on the JIT and requires a restart to apply C# edits in 0.15. Remote, Release and browser WebAssembly client code also require a restart.
- **Time-travel debugging.** **Debug > Start with Recording** records shallow state in a configurable ring buffer, 64 MiB by default. Step Back, Step Back Into, Reverse Continue and the timeline inspect previous steps; debugger panes and DataTips mark historical values. **When did this change?** finds recorded writes. The IDE entry point covers local in-process C# console projects. Inspecting history does not replay input/output or invoke user getters. During a recording, applying C# edits requires **Restart to apply edits** and starts a new recording; Continue without edits, or after reverting the edits, resumes the existing recording.
- **Offline AI.** Select Local agent mode or enable inline completions for ghost text in any editor language. Tab accepts a completion; typing or Escape cancels it. Optional Qwen GGUF downloads have pinned revisions, size and SHA-256 checks, and individual license acceptance. The manager shows estimated memory and speed measured on the device, and can unload or delete a model. Inference runs through llama.cpp in a 64-bit build; local prompts stay on the device and file changes use the existing proposal approval flow. Background completion pauses when the device is hot or its unplugged battery is low.

- **Microchip PIC.** Create PIC18/PIC32 Blink projects or open MPLAB X projects with their generated makefiles. On 64-bit Android, install the verified official XC8/XC32 compilers after accepting Microchip's license; the compilers remain user-installed and are not redistributed. Builds report diagnostics and memory usage, and clangd uses the device headers and compiler definitions. PIC18 models supported by gpsim gain local F5 debugging. A serial monitor and configured USB-OTG bootloader/programmer routes support compatible boards; other programming and on-chip debugging routes use the Windows Bridge. Compiler translation runs in separate Linux processes while the IDE keeps its JIT. See [PIC setup and supported devices](../PIC.md).

## Fixed

- The emulator self test is divided into parallel shards, retaining every assertion and giving each group its own time budget and logs. The release passes only when every shard passes.
- CI rejects retries for the merged feature tests and for incomplete test runs or build errors. An unrelated test may retry once, with its first failure and `FLAKY.txt` retained for review.
- Screenshot tests close their windows and drain pending UI work before headless font teardown, preventing stale layout work from aborting the IDE test host.
- Native-runtime source downloads log their URLs, retry transient transport failures and use official fallback endpoints while retaining the pinned SHA-256 checks.
- Converted Avalonia projects retain local XAML resource/style includes, automatic grid tracks and mapped event behavior. Port notes identify approximations that need review.
- Stopping a Windows Forms test waits for its actual exit notification instead of racing a closed message queue.
- Fast remote SSH commands can finish before the IDE closes their input; closing an already completed command now succeeds without hiding other stream errors.
- PIC target setup and flashing honor the workspace's local/remote state; SSH source caches continue to use their remote run profile.
- Language servers that lose their connection during initialization use the existing bounded crash-recovery policy. Invalid responses, missing tools and initialization timeouts still report failures.
- Native process checks retain the full 200-process stress sequence before toolchain preparation and verify child IDs, output and exit status across collections. Desktop tests retain the real metadata-update assertions; Android checks its explicit JIT/runtime capability boundary.
- Native descriptor flags use a full-width variadic argument on Android, avoiding a libc abort when Mono leaves the upper register bits unspecified.
- Android no longer enables the process-wide Mono interpreter to support Hot Reload. The original local-inference backend is retained, and a controlled emulator comparison measures F5 and completion latency with the interpreter and with the production JIT configuration.

## Install

1. Download `TabStudio-0.15.0.apk` below on your tablet.
2. Open the APK and allow installing apps from your browser or file manager when Android asks.
3. Install optional toolchains from **Tools > Toolchain Store**. The first package, SDK and model downloads need an internet connection. Keep Android System WebView up to date for web previews.

Requires Android 9 or later on 64-bit or 32-bit ARM, with 3 GB of memory or more (2 GB with TabStudio Link). Local AI requires a 64-bit build; model memory requirements appear in its manager. It installs as an update over 0.14.

## Verified

The integration pipeline defines checks for every library, the real IDE in both themes, APK signature verification, every Android emulator shard, Windows Bridge on Windows, and the merged features' dedicated SSH, mobile, PIC and local-inference jobs. PIC verification includes real XC8/XC32 builds on x64 and ARM64, native programmer/gpsim checks and an Android app-UID compiler probe. CI has no physical PIC board or programmer; the supported hardware routes and their limits are documented in the PIC guide. All emulator shards are required for the release gate. The integration PR records the checked SHA, CI results and measured shard timings. Merged feature tests must pass on their first attempt; only failures outside those features may use the single retry, with the first-attempt log and `FLAKY.txt` retained for review.
