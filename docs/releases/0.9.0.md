TabStudio 0.9 runs Windows Forms apps on the tablet, and designs them by touch.

## What's new in 0.9

- **Windows Forms apps.**
  - Projects with `<UseWindowsForms>true</UseWindowsForms>` or a `net10.0-windows` target build on the tablet against TabStudio's own Windows Forms layer, which has the exact `System.Windows.Forms` and `System.Drawing` names, so code from Visual Studio compiles unchanged. IntelliSense works in them.
  - F5 runs the app in the app preview inside a Windows 10 window. `Show` and `ShowDialog` open more windows, closing the main form ends the run, and `Console` output goes to the Output panel. An unhandled exception ends the app, never the IDE.
  - Saving a file restarts the app.
  - A new **Windows Forms App** template, file for file as in Visual Studio.
  - The Compatibility Doctor lists C# Windows Forms projects as ready, and says plainly that code calling Windows itself (P/Invoke, COM, the registry) does not run on the tablet.
- **The Windows Forms designer, built for touch.**
  - `Form1.cs` opens on Design, as in Visual Studio. Code (F7) and Design (Shift+F7) switch between them.
  - Tap a tool in the Toolbox and then the form, or drag it there. Drag controls on an 8-pixel grid, and resize them by their handles.
  - The Properties panel edits Name, Text, Font, colors, alignment, Location, Size, Anchor, Dock, Padding and more, and its Events tab names handlers.
  - Double-tap a control to write its default event's handler in `Form1.cs` and jump to it.
  - Menus and tool strips are typed in place in "Type Here".
  - Undo and Redo, Cut, Copy and Paste, Delete, Bring to Front and Send to Back. Renaming a control renames it in `Form1.cs` too.
  - The designer reads `InitializeComponent` without running the app's code, and writes `Form1.Designer.cs` as Visual Studio does, so the project still opens on a PC.

## Fixed

- Solutions that set properties in `Directory.Build.targets`, such as Piranha CMS turning on implicit usings there, now build on the tablet. Before, every file lost its implicit `using System` and thousands of errors appeared.
- The start screen's template tags have their text centered.
- Tapping a template on the start screen brings its options, the project name and **Create and open** into view.

## Install

1. Download `TabStudio-0.9.0.apk` below on your tablet.
2. Open it and allow installing apps from your browser or file manager when Android asks.

Requires Android 9 or later on 64-bit or 32-bit ARM, with 3 GB of memory or more (2 GB with TabStudio Link). It installs as an update over 0.8.

## Verified

Every commit runs these checks in CI:

- the unit tests of every library, including the Windows Forms layer, and the designer reading, editing and writing `Form1.Designer.cs` files that then compile;
- headless UI tests that type, tap and press keys in the real IDE, with screenshots. They include a Windows Forms app that runs, restarts on save and survives its own crash, and the designer moving, resizing and adding controls, editing properties and writing a Click handler;
- an APK build with signature verification;
- the app on an Android tablet emulator. There it:
  - runs the sample and answers its question;
  - debugs it to a breakpoint, both on the tablet and through a TabStudio Link host;
  - checks a language server and a debug adapter;
  - serves a new ASP.NET Core app, a Blazor WebAssembly app's boot files and a Blazor Web App with no errors;
  - shows a new Avalonia app;
  - installs a grammar extension from Open VSX and colors its file;
  - installs Python and Node.js from Alpine Linux's real mirror and runs a program with each, and debugs Python to a breakpoint;
  - runs a new Windows Forms app, and adds a button to it in the designer;
  - runs desktop mode on a second display.

This release was published by CI only after its own build passed all of them.
