TabStudio 0.14 builds and debugs Go, Rust, C/C++ and Java on the tablet, and runs WPF and WinUI apps beside their code.

## What's new in 0.14

- **WPF on the tablet.**
  - Create a WPF Application or open a C# WPF project and press F5. OpenSilver 3.3.3 builds its XAML and runs it in the web preview; saving restarts it, and console output and exceptions appear in Output.
  - XAML has completion, Quick Info, Go to Definition, live errors and a light bulb that adds a missing event handler without losing unsaved code-behind.
  - Unsupported APIs are named in diagnostics, with the Windows Bridge available for projects that need Windows itself.
- **WinUI 3 and Uno Platform.**
  - Both have Start templates and Ready compatibility reports. F5 builds on the tablet and runs the app in-process through Uno's native Skia renderer beside the editor.
  - Saving XAML or C# rebuilds and restarts the preview. XAML compilation errors point to their source lines.
- **Go.** Go modules, including nested modules, appear in the startup menu. gopls provides IntelliSense and navigation; Ctrl+F5 builds and runs with Output-panel input, and F5 debugs with Delve.
- **Rust.** Cargo packages, workspaces and workspace members are selectable startup projects. rust-analyzer provides IntelliSense; Cargo diagnostics link to the source, and F5 uses LLDB with Cargo's reported executable paths.
- **C and C++.** Open a CMake project, a Makefile or standalone source files, or create a C++ Console App. clangd provides IntelliSense, CMake exports a compilation database, compiler errors link into Error List, and F5 debugs with LLDB.
- **Java.** Create a Java 21 Maven app or open Maven, Gradle or standalone Java sources. JDT LS provides IntelliSense and java-debug supplies F5 debugging. Builds use their dependency classpaths and console input stays in the Output panel.

## Fixed

- Portable C/C++ projects use their tablet toolchain alongside the Windows Bridge's Visual C++ support.
- Debugger startup failures retain the adapter's error output. Native debugger input uses a private FIFO without mixing console text into the debug protocol.
- Go debugging uses an app-private socket on Android. Rust's emulator check inspects live locals and waits for cleared breakpoints before continuing.
- Java's VM mapping shim is enabled inside Alpine, after Android starts PRoot. Maven errors link to their files for Windows and relative paths.
- Replayed WebView taps release through Android's gesture queue so a busy IDE does not turn a tap into a long press.
- The combined emulator self test retains the existing checks and every new feature check within its 15-minute limit.

## Install

1. Download `TabStudio-0.14.0.apk` below on your tablet.
2. Open the APK and allow installing apps from your browser or file manager when Android asks.
3. Install a language from **Tools > Toolchain Store** when prompted. The first toolchain and dependency downloads need an internet connection. Keep Android System WebView up to date for the WPF preview.

Requires Android 9 or later on 64-bit or 32-bit ARM, with 3 GB of memory or more (2 GB with TabStudio Link). It installs as an update over 0.13.

## Verified

Release checks include every library's unit tests, the real IDE's headless tests in both themes, a signed APK build and signature verification, the full Android emulator self test, and the Windows Bridge tests on Windows. The emulator exercises WPF, WinUI and each new language alongside the existing Forms, web, Avalonia, Swarm, scrolling and desktop-input checks. The new feature checks pass on their first attempt; any accepted retry of an unrelated test is recorded in `FLAKY.txt`.
