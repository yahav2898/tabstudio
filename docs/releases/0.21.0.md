TabStudio 0.21.0 runs real containers on an Android tablet, with no root and no Docker. Images from Docker Hub and other
registries run under TabStudio's own PRoot as the app's user, so a repository whose Compose file starts PostgreSQL,
Redis or nginx starts them with F5, and its app answers on the tablet as it does on a computer.

## New

- **Images from any OCI registry.** Docker Hub and other v2 registries, with sign-in for private ones. TabStudio picks
  the image built for the tablet (ARM64, then ARMv7, then amd64), checks every layer's SHA-256, keeps each layer once
  however many images share it, and shows the download in the progress bar, where it can be cancelled.
- **Containers that run as the app.** An image's entrypoint, command, environment, working folder and user run under
  PRoot as TabStudio's own Android user. Each container has its own writable files, volumes and mounts, logs, a
  terminal into it, stop and restart. Every container gets its own loopback address and its ports are published on
  the tablet, so two databases on the same port run side by side.
- **Compose with real images, from F5.** Services starts a repository's Compose images in dependency order, waits for
  their health checks and passes the app its connection settings. When an image cannot run here, Services falls back
  to the native Alpine service it used before and says which one and why. A backend opened from a subfolder finds the
  repository's Compose file.
- **View > Containers.** Images, containers, ports and logs, registry sign-in and a terminal into any container, in
  the design system and at every text size.
- **`docker` in the terminal.** `pull`, `run`, `ps`, `images`, `logs`, `exec`, `stop`, `restart`, `rm` and
  `compose up`/`down` work in TabStudio's terminal.

## Limits

No root and no privilege escalation are used, and Android's app sandbox is unchanged. PRoot gives no kernel
isolation: there are no cgroups, read-only mounts are not enforced, and containers are not isolated from each other.
Only TCP ports are published, and only gzip and plain tar layers are read. Each container's writable files are a full
copy, so storage use can be large, and Android may stop containers when memory runs low. ARM64 images are preferred;
amd64 images run through Box64 and are slower.

Dockerfile builds, dev containers and the Docker Engine API come later. The
[containers guide](https://github.com/yahav2898/tabstudio/blob/main/docs/features/containers.md) lists what works, the
limits and the measurements.

## Install

1. Download `TabStudio-0.21.0.apk` below on your tablet.
2. Open it and allow installing apps from your browser or file manager when Android asks.

Requires Android 9 or later on 64-bit or 32-bit ARM, with 3 GB of memory or more (2 GB with TabStudio Link). It installs
as an update over 0.20.

## Verified

Every commit runs the unit tests of every library, headless UI tests of the real IDE in both themes, an APK build with
signature verification, and the full self test on an Android tablet emulator. A new containers job pulls and runs real
PostgreSQL, Redis and nginx images on ARM64 and x64 and checks registry sign-in, layer integrity and Compose, and a new
emulator shard checks that containers run as the app's user and that nginx serves the web preview. The FastAPI full
stack template, pinned to a commit, starts its database from its own Compose files with F5, applies its migrations and
answers its login and items routes; gothinkster's Node RealWorld app answers its first database-backed route the
same way.
