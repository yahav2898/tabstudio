# 0.21.0 — Containers without root

Release candidate. The product version remains unchanged until release integration; this branch must not publish
or merge itself.

## New

- Pull and verify Linux OCI images from Docker Hub and other v2 registries, with platform selection, session
  registry credentials, shared layer storage and long-operation progress.
- Run image entrypoints under the APK's PRoot as the Android app's own UID. Each container has writable files,
  volumes, environment, logs, exec, stop and restart. Independent loopback addresses and TCP port mapping prevent
  guest-port collisions.
- Services attempts real Compose images before a named native Alpine fallback. F5 keeps the existing dependency
  selection and connection-environment rewriting.
- **View > Containers**: images, containers, ports, logs, registry sign-in and an interactive exec terminal.
- The local terminal's `docker` subset: pull, run, ps, images, logs, exec, stop, restart, rm and compose up/down.

## Verification

The new OCI CI matrix exercises registry authentication, integrity, layer handling, Compose and real PostgreSQL,
Redis and nginx on x64/ARM64. A separate Android self-test shard checks the real app UID and nginx WebView.
The original trial sweep's pinned FastAPI repository uses its upstream Compose files through F5; its database
connection, migrations, login and items route are checked too. The additional RealWorld Node regression uses an
explicit Compose fixture and requires its first database-backed route through F5. Final CI status, screenshots and measurements are recorded in the
[containers guide](../features/containers.md) and PR #36 before this candidate is marked ready.

## Limits and deferred work

No root or privilege escalation is used. PRoot does not provide kernel isolation, cgroups or enforceable read-only
mounts. Only TCP publishing and gzip/plain-tar image layers are supported. Writable container roots are full
copies, so storage can be substantial; Android can stop processes under pressure. Native ARM64 is preferred;
amd64 glibc translation needs the prepared Box64 runtime and is not performance-qualified.

Dockerfile builds, development-container execution and the Docker Engine API are deferred. See the
[full compatibility and verification notes](../features/containers.md).

## Installation

Once release integration and all required checks pass, install the signed `TabStudio-0.21.0.apk` from GitHub
Releases over the previous version. During review, use the APK artifact from PR #36. No uninstall, root access or
companion app is required.
