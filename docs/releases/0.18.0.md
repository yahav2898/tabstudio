TabStudio 0.18 lets several tablets and phones code together in real time with no cloud, lets Windows Forms apps draw on images and fits WPF windows in the preview, runs packages with native libraries, and opens real Python, Java and Rust repositories from GitHub and runs them with one F5.

## What's new in 0.18

### TabStudio Live

- **TabStudio Live.** **File > Share Session** shows a QR code and a short code; another TabStudio scans it, or types the address and code, with **File > Join Live Session** or **Join Live** on the start screen. The guest gets a copy of the shared workspace and opens the same solution. The connection is TabStudio Link's: TLS between the two devices, with the host's certificate pinned by the QR code, and nothing goes through a server. See [the guide and its security model](../features/live.md).
- **Type at the same time.** Every open document is shared as it is typed, in any language. Edits made at the same moment merge on every device into the same text (a sequence CRDT of TabStudio's own), a guest whose Wi-Fi drops keeps typing and merges when it reconnects, and Undo takes back only your own edits. Each participant's caret and selection show in their color with their name, and avatars on a tab show who else has it open. IntelliSense runs on each device, on its own copy of the files.
- **Follow.** Tap **Follow** beside a participant in the **Live Share** window to see the file they show, their selection and how far they scrolled, until you type or tap.
- **Run and debug together.** The host builds and runs. Its Output, Terminal and Error List show on every guest, breakpoints are shared, and when the program pauses every device marks the same statement and shows the same call stack, locals, watches and DataTips. The host decides who may continue and step, and who may type in the Terminal.
- **Classroom.** One presenter, everyone else following by default, for a class of up to 32 devices: students raise a hand, and the host can hand control to one of them and take it back.
- **The host decides.** Guests can edit or only watch; the host can change that for each guest, lock the session, and remove a guest at any time. Guests never see files outside the shared folder, and their copies are deleted when the session ends.

### Windows Forms, WPF and NuGet packages

- **Draw on images in Windows Forms apps.** `Graphics.FromImage(bitmap)` works: lines, shapes, paths, curves, text, images, transforms, clipping, antialiasing, pen caps, joins and dashes, and solid, gradient, texture, hatch and path gradient brushes draw into the bitmap's pixels as GDI+ does. Tests compare 21 scenes with pictures GDI+ drew on Windows. A picture box shows what was drawn on its image after `Invalidate` or `Refresh`, a bitmap can be drawn into another or into itself, and `Image.Save` writes PNG, JPEG (with a quality setting), BMP, GIF and ICO files. `new Bitmap(image)`, `Clone(rectangle)`, `RotateFlip`, `MakeTransparent`, `LockBits` and `UnlockBits` (32-bit ARGB and 24-bit RGB, with `Marshal.Copy`), and `GetPixel`/`SetPixel` agree with what was drawn. A paint program whose `Load` handler called `Graphics.FromImage`, which crashed with `NotSupportedException` in 0.17.0, runs, draws strokes with the mouse or a finger, and saves them.
- **Drawing without flicker.** `DoubleBuffered`, `BufferedGraphicsContext`, `BufferedGraphicsManager` and `BufferedGraphics`, and `Control.DrawToBitmap`, which games use to save a picture of the board.
- **Images from `.resx` files.** Images, icons and files the designer stores in `Form1.resx` and `Properties/Resources.resx`, and `ImageList.ImageStream`, load as on Windows; the image list is read from the .NET Framework's serialized form when the project builds, without the binary formatter. `Clipboard.SetImage` and `Clipboard.GetImage` go through Android's clipboard, so a picture copied in an app pastes into other apps. `GraphicsPath.AddString` adds the outlines of text.
- **Fewer things Windows Forms apps cannot do.** Every `NotSupportedException` in the Forms layer was reviewed, and what tutorial apps reach for now works: MDI parents and children (children are windows in the parent's workspace, with title bars to move, minimize, maximize and close them, `LayoutMdi` and the Window menu's list), forms inside panels, `RichTextBox.Rtf` and RTF files (their text), `Application.Restart`, `Application.AddMessageFilter`, `Graphics.FromHwnd`, `ImageAttributes` color matrices, custom and arrow line caps. What remains needs Windows itself, such as GDI handles (`Graphics.GetHdc`, `Bitmap.GetHbitmap`); the [Forms layer's README](../../src/TabStudio.Forms/README.md) lists each one and why.
- **WPF windows fit the web preview.** A WPF window larger than the preview now shows whole: **Fit** (the default) scales it down to the pane, **100%** shows it at its own size with scrolling, and **Fill** stretches it to the pane as before. The choice is in the preview's toolbar and is remembered for each project. Pinch to zoom and pan with two fingers. The scaling is the browser's own page zoom, so OpenSilver's layout, text measuring and pointer positions are unchanged and a tap lands on the control under the finger at every zoom.
- **Packages with native libraries run.** NuGet packages now run with their runtime-specific assemblies (`runtimes/{rid}/lib/{tfm}`) and native libraries (`runtimes/{rid}/native`), chosen along the RID graph from the tablet's own (`android-arm64` falls back to `linux-arm64`, `linux`, `unix` and `any`), from the packages' `runtime.json` and the SDK's graph, as NuGet and the .NET host do. Microsoft.Data.SqlClient no longer fails with "Microsoft.Data.SqlClient is not supported on this platform", Microsoft.Data.Sqlite finds `e_sqlite3`, and programs, tests, notebooks and the debugger resolve native libraries from those folders, reusing those TabStudio already has, such as SQLite and SkiaSharp. SimplCommerce, which crashed this way in 0.17.0, now serves its first page.
- **Honest about SQL Server.** SQL Server does not run on an ARM tablet. When a project uses it and nothing answers at the server in its `appsettings.json`, the Compatibility Doctor says **Needs a database** and F5's Output says so once, in plain words, instead of ending with a bare stack trace, and offers the choices: connect to a SQL Server on your network or in the cloud (the form is prefilled from `appsettings.json`, and the connection is saved encrypted in the Database Explorer and used by every run), or, when the project supports it, switch to PostgreSQL in Services or to SQLite.

### Python, Java and Rust repositories

### Python: the version the project needs, and packages that must be compiled

- **The Python the project asks for.** Before creating `.venv`, TabStudio reads the version a project names in
  `.python-version`, `runtime.txt`, `pyproject.toml` (`requires-python`, or Poetry's `python`), `Pipfile` or the
  `FROM python:X` of its `Dockerfile`. Within what it allows, it takes the newest Python its pinned packages install
  on from prebuilt wheels, not always the newest Python: Alpine's Python is 3.14, and microblog's pins (psycopg2-binary
  2.9.9, multidict 6.0.4, greenlet 3.0.1) ship wheels up to 3.11, so microblog gets Python 3.11 and installs in
  seconds without compiling anything. A version other than the toolchain's own is installed by uv, from its musl builds
  of CPython; the Output panel says which version was chosen and why.
- **Packages that must be compiled get what they build with.** When pip has to compile a package and the build fails
  for want of a compiler or a library, TabStudio installs `build-base` and `python3-dev`, and the libraries known
  packages build against, and runs pip again: psycopg2 gets `libpq-dev` (PostgreSQL's `pg_config` and headers),
  mysqlclient `mariadb-dev`, lxml `libxml2-dev` and `libxslt-dev`, Pillow `libjpeg-turbo-dev` and `zlib-dev`, cffi
  `libffi-dev`, cryptography `openssl-dev`. The table is data, `src/TabStudio.Toolchains/Python/python-build-packages.json`,
  with a map from missing C headers to their packages for everything else.
- **One message instead of 34 folded lines.** A failed install says which package failed, why, and what TabStudio did
  or what helps, such as "psycopg2-binary 2.9.9 could not be installed: it has no prebuilt wheel for Python 3.14 on
  this tablet, so pip compiled it, and PostgreSQL's pg_config was missing." pip's full output is in the new
  **Project Setup** log of the Output panel, and the notice over the editor opens it with **Show Full Log**.
- **Flask and Django apps run.** A project with `.flaskenv` runs `flask run`, and one with `manage.py` runs
  `manage.py runserver`, so F5 starts microblog, and the web preview offers its page.

### Java: Compose services that stay out of the way

- **Missing bind sources are created.** A bind volume whose source folder does not exist, such as PetClinic's
  `./conf.d:/etc/mysql/conf.d:ro`, is created as an empty folder when its service starts, as Docker does, for the
  short syntax and for the long syntax unless it sets `create_host_path: false`.
- **Errors stay on their service.** One service's problem no longer marks the whole Compose file "could not be
  read" or stops the others: an unsupported setting makes that service unavailable with its reason, a failed start
  shows on its row with a summary over the list, and a service that depends on a failed one says which.
- **Nothing downloads or starts by itself.** Opening a repository reads its Compose file and offers its services.
  F5 starts only the services the run configuration points at: a connection string or URL in the run's environment,
  `.env`, `appsettings.json`, or the settings of the active Spring profiles. PetClinic runs on in-memory H2 by default,
  so F5 starts neither MySQL nor PostgreSQL; with the `postgres` profile it starts PostgreSQL alone. MySQL's
  `MYSQL_ALLOW_EMPTY_PASSWORD`, which PetClinic uses, now works.

- **PetClinic runs on its default profile.** A Maven program now runs on its runtime classpath, as Gradle's already
  did. Dependencies of every scope were copied onto it, so PetClinic's test-only `spring-boot-docker-compose` ran
  `docker compose up` when the app started; without Docker, as on a tablet, the app failed to start. F5 now starts
  PetClinic on in-memory H2, and its site answers in the web preview.

### Rust: the Cargo project, not its Makefile

- **A Makefile that wraps another build tool is not a C/C++ project.** fd's Makefile runs `cargo build --release`;
  it no longer becomes the startup project. A Makefile that only runs cargo, npm, go or dotnet is skipped, and when a
  folder has both a language manifest and a Makefile that builds C, the manifest comes first.
- **Programs are named after their binary.** "The program 'fd' has exited with code 0", never 'Makefile'. CMake and
  Makefile builds name the target they built, and the message when a build leaves several programs says which.

### Every toolchain: Output colored by what it says

Cargo, pip and Gradle write their progress to standard error, so every "Compiling …" line was red. The Output panel
now colors each line by what it says: compiler errors and warnings with their source excerpts, build tools' error and
warning levels, log levels, Python tracebacks, Rust and Go panics, and JVM and Node.js exceptions. Warnings have their
own color. Everything else, on either stream, is ordinary output.

## Install

1. Download `TabStudio-0.18.0.apk` below on your tablet.
2. Open the APK and allow installing apps from your browser or file manager when Android asks.
3. Install optional toolchains from **Tools > Toolchain Store**. The first package, SDK, service and model downloads need an internet connection; TabStudio Live does not.

Every device in a session needs the same version of TabStudio. Requires Android 9 or later on 64-bit or 32-bit ARM, with 3 GB of memory or more (2 GB with TabStudio Link). It installs as an update over 0.17.

## Verified

Unit tests cover the text CRDT (concurrent edits in random order on several replicas converge to the same text, edits made offline merge after a reconnect, duplicates and out-of-order operations, per-participant undo), the protocol's messages and invitations, paths and permission rules. Session tests run a host and guests over the real encrypted transport: three devices typing at once, a viewer's forced edit refused, a removed guest refused on rejoin, a reconnect with offline edits, a class of 30 with raised hands and handed control, and the shared debugger. IDE tests run two and five TabStudio IDEs in one process: typing at once, Follow, a guest's breakpoint pausing the host's program on both devices, a read-only guest and a removed guest, with screenshots of two devices editing together. The emulator's self test shares the sample and joins it from a second client in the app. The pull request records the CI results.

Unit tests render 21 drawing scenes into bitmaps and compare them with reference PNGs that GDI+ drew on a Windows runner, within a tolerance for antialiasing, and cover pixels, `LockBits`, saving in every format, `.resx` images and image lists (checked against what Windows Forms decodes), the clipboard, `AddString`, double buffering, `DrawToBitmap`, RTF, MDI, message filters and `Application.Restart`. An IDE test runs a paint program, draws strokes with simulated mouse drags, saves the picture and checks its pixels. Another opens a WPF window wider than the preview: in Fit the whole window is visible and a tap on its right-most button reaches the app, and at 100% the page scrolls and a tap still lands; a library test does the same in the real OpenSilver page on a phone-sized browser. The device self test copies a picture to Android's clipboard and pastes it back, and checks that the WPF template's window is whole in Fit. Unit tests select assets from the real layouts of Microsoft.Data.SqlClient 5 and 6, System.Data.SqlClient, SQLite and SkiaSharp; an IDE test runs a console program that builds a `SqlConnectionStringBuilder` and queries SQLite through `SqliteConnection`, and another checks the SQL Server message and its choices on two real F5 runs. The device self test checks that a program's `e_sqlite3` resolves on Android. The **Real repositories** job adds SimplePaint, a Windows Forms drawing app, a Windows Forms snake game and a classic WPF calculator, pinned to commits, and SimplCommerce, which it builds and runs against SQL Server in a service container until its first page is served. The pull request records the checked SHA and CI results.

Unit tests cover each rule: reading a Python version from every file that names one and PEP 440 and Poetry
specifiers; requirements pins with includes, markers and hashes; wheel tags (CPython, stable ABI, pure, musl and glibc)
and the newest version a set of pinned releases installs on; the build-package table; pip failures for missing
`pg_config`, compilers and headers, versions that do not exist for a Python, conflicts, the network and storage;
Makefiles that wrap Cargo, npm, Go, .NET and Yarn and ones that build C; startup project order and program names; Output
classification for Cargo, rustc, Python, pip, Java, Spring Boot, Maven, Go, Node.js, npm and C compilers, in pieces of
any size; Compose bind sources with both syntaxes, per-service parse and start errors, and which services a run points
at, including PetClinic's profiles.

IDE tests open a Python repository whose C extension fails to compile (one message, the full log one tap away, then
an install and a run once the header is there), a Compose file with a missing bind source, an unsupported service and
an optional one (nothing starts on open or F5, a failed start stays on its row), a Cargo repository with a wrapper
Makefile (the Rust startup project, the binary's name, ordinary Cargo progress and a warning in its color), and, in the
Alpine harness, F5 starting only the PostgreSQL a run points at while MySQL's start creates its bind folder.

The **Real repositories** job now also opens microblog, spring-petclinic and fd, pinned to commits, with Python 3.12
and uv, OpenJDK 21 with Maven, and Rust. The IDE sets each up and Ctrl+F5 runs it: microblog's Flask app and
PetClinic's Spring Boot site, on its default H2 profile, must answer their first page in the web preview, and fd must
list the repository's files and exit with code 0.
