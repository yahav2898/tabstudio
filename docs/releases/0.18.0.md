TabStudio's proposed 0.18 embedded work adds native firmware project workflows, permissioned USB bridges and
tools for understanding and safely programming firmware. This branch is experimental: it does not change the
product version or publish a release, and it does not claim physical-board verification.

## What's new in 0.18

- **Native embedded projects.** Detect PlatformIO, Arduino sketches/library examples, generated STM32Cube builds,
  ESP-IDF, Zephyr, Pico SDK, embedded Rust and board Python. Build with the owning CLI and keep native configuration.
  The Store adds ARM/RISC-V/AVR GCC, pinned PlatformIO Core and Arduino CLI, plus native glibc recipes for
  ESP-IDF, Zephyr, Pico SDK and embedded Rust. Third-party board/core packages retain their own compatibility requirements. Board starters use actual upstream identifiers.
- **USB permissions carried into Linux tools.** The PIC libusb descriptor bridge is reused and made safe across
  contexts. A raw PTY plus scoped termios/ioctl bridge forwards serial format, arbitrary baud, DTR/RTS, break and
  hangup to existing CDC-ACM/CH340/CP210x/FTDI drivers. These routes cover compatible dynamically linked clients;
  a separate PRoot syscall bridge also routes stock nusb and static USB clients through a private permissioned
  inventory. OpenOCD can select the signed HIDAPI-libusb backend for CMSIS-DAP v1. Native probe-rs hidraw and
  static/direct-syscall serial controls remain separate limits.
- **Application upload and on-chip debug.** Typed flash profiles parse the actual image, enforce application
  address boundaries and bind plans to its SHA-256. Verified routes require upstream target checks or independent
  readback. Teensy HalfKay can report transport completion explicitly without claiming readback verification. Official probe-rs DAP and the OpenOCD/Python-enabled all-target GDB fallback attach through the existing debugger UI. Exact probe,
  chip, installed scripts and matching ELF are required; attaching does not silently reprogram the target.
- **Additional bootloader routes.** WCH ROM ISP checks the reported chip before flash/verify; MSP430 mspdebug
  disables startup scripts and performs target-memory comparison. Nordic SDK Secure DFU accepts only a checked
  application ZIP through legacy pc-nrfutil 6.x; it refuses SoftDevice/bootloader/debug packages. AVR UART UPDI
  reuses existing pinned pymcuprog wheels with readback verification and no high-voltage/unlock operation.
  Teensy supports exact-board HEX transfer with an explicit **readback unavailable** outcome and cannot enter
  verified production batches. Flash profiles automatically install pinned esptool/picotool native distributions or
  source-built BOSSA, Teensy, WCH and MSPDebug clients through the Store. Signed Alpine packages supply stm32flash
  and legacy libusb compatibility. Legacy pc-nrfutil's Python <3.11/native dependency constraints leave its automatic
  ARM64 installer unavailable; an explicitly installed compatible CLI is required. Physical-board programming is unverified.
- **ESP first-flash metadata.** Actual IDF/SCons build metadata supplies distinct bootloader, partition and app
  images with checked offsets and header settings. Each image is verified separately; gaps, NVS and filesystem
  partitions are preserved. Secure boot/encryption configurations that could alter eFuses are refused.
- **Backups, batches and Wi-Fi.** Application backups require two matching reads; dump comparison reports exact
  differing-byte counts and hashes. Parallel production workers keep independent USB connections, verify each
  board and save JSONL result logs. ArduinoOTA-compatible upload requires the board's final acknowledgment and
  an already installed OTA application; that acknowledgment is distinct from physical readback.
- **BOOTSEL UF2 through Android USB Host.** A permissioned BOT/SCSI worker and bounded FAT12/16/32 writer copy
  a family-checked application UF2 to identified RP2040/RP2350 ROM volumes without mounting a disk. Existing
  files, application boundaries and FAT metadata are checked before writes. Results distinguish command
  acceptance, optional filesystem-sector readback and unconfirmed ROM disconnection from actual flash verification.
- **Memory, crash, stack and pin analysis.** ELF section treemaps and symbol/object attribution expose linked
  memory use and previous-build changes. Crash flags/backtraces can resolve through the matching ELF. An explicit
  supported Cortex-M profile can capture live fault status from an unchanged halted GDB session; stack recovery
  additionally proves the fault-entry PC and known EXC_RETURN layout. GCC stack
  records and final compiler `.ci` call graphs check task budgets while keeping unknown whole-program bounds explicit. Pin checks read
  bounded explicit assignments and an optional exact-chip pin map.
- **Registers, RTOS and everyday editing.** Load a CMSIS-SVD for register/field descriptions and halted-target
  inspection. Ordinary field writes require a separate reviewed allowlist, exact confirmation and readback.
  Hover adds register descriptions; a matching device header enables existing verified mask macros as Ctrl+.
  actions. RTOS readers use real debug types rather than hard-coded layout offsets.
- **Tests and board Python.** Host Unity/TAP/GoogleTest/Cargo results, verified application-only `probe-rs run`
  board-test plans and imported decoded target logs appear in Test Explorer with their actual host/board identity.
  Native Unity RTT, defmt-test and embedded-test acquisition is implemented but hardware-unverified.
  mpremote opens the existing Terminal as a board REPL and
  copies the active Python file with separate readback verification.
- **Source-preserving import.** Keil ARM, IAR ARM/AVR and Atmel/Microchip ARM/AVR8 metadata can create an independent
  GCC/CMake project. Structured notes retain unresolved startup, linker, ABI, language-extension and custom-step
  work; the original is never changed and an import is not labeled as a successful firmware build.

## Fixed and guarded

- Application upload cannot silently include bootloader/configuration memory or use a stale image after planning.
- Exact reviewed LPC175x/176x and K64 parts also inspect in-image CRP/FCF bytes inside ordinary flash.
  Protection values and unknown partial configuration are refused before erase; an all-FF Kinetis FSEC is unsafe.
- A failed verification, missing final protocol acknowledgment or incomplete test harness cannot become success.
- Generic USB-serial IDs do not identify a target MCU. Missing register metadata, source symbols, memory regions,
  call edges or stack initialization settings remain unknown rather than inferred as verified facts.
- eFuse burning and permanent read-out protection/RDP level 2 are refused. No general fuse/option-byte write UI
  is added; the configuration policy requires an exact operation-specific confirmation for future supported writes.

## Install

Use the PR's Android APK artifact to test this branch. It is not a published 0.18.0 release, and
`Directory.Build.props` retains the current version. Toolchain/core/SDK downloads require internet access and
retain their upstream licenses. See [the embedded guide](../features/embedded.md) before selecting a hardware route.

## Verified

The change includes managed parser/protocol/planner tests, real IDE command tests/screenshots, a compiled POSIX
client exercising the production serial bridge, synthetic libusb/adapter fixtures, and an Android virtual-device
self-test. Real Cortex-M and RV32 firmware has locally passed the cross-compile → QEMU → GDB DAP → TabStudio
client path with breakpoints, locals, stack, stepping and memory. AVR/simavr also passed locally through a real
AVR-enabled GDB 15 Python/DAP build, including source breakpoints, locals, stack, stepping and instruction output.
The final PR records which CI jobs completed on its exact push and pull-request SHA.

Seven public embedded repositories are pinned in the Real repositories manifest with zero-error native build
baselines. These jobs test host ecosystem builds; they do not prove ARM64 Android SDK installation or physical
USB programming. No real USB/serial captures or hardware-verification claims were fabricated. Every board/probe
and the remaining transport, programmer, package-compatibility, RTT/defmt and automation limits are listed in
[the coverage tables](../features/embedded.md).
