TabStudio 0.20.3 reads .NET solutions as the .NET SDK reads them, and starts the project a person would choose.
Large real solutions opened with errors Visual Studio does not show: MSBuild conditions were not evaluated, items of
imported files and packages' targets were missing, and a solution's own build settings were ignored. Of 54 .NET
solutions opened and built as a person would, 48 now show no errors, where 30 did, and MudBlazor (294 errors), eShop
(268), NodaTime (2,320) and Ocelot (647) are among them. The other six need a newer C# compiler, an older framework,
or code that an MSBuild task writes, as the end of these notes says.

## Fixed

### Projects are evaluated as MSBuild evaluates them

- **Conditions and property functions are evaluated.** A property set in a `Condition="'$(Configuration)' == 'Release'"`
  group, or for another target framework, was applied anyway: the first value written won. Properties are now
  evaluated in MSBuild's order (`Directory.Build.props`, the packages' props, `Directory.Packages.props`, the project,
  the SDK's targets, the packages' targets, `Directory.Build.targets`), with the global properties Visual Studio uses
  (`Debug`, `AnyCPU`) and, for a multi-targeted project, the inner build of its first framework. Conditions support
  every operator MSBuild has, and property functions are evaluated: `$([MSBuild]::IsTargetFrameworkCompatible(...))`,
  `GetPathOfFileAbove`, `GetDirectoryNameOfFileAbove`, `System.IO.Path`, `Directory.GetParent(...).Parent.FullName`,
  string, version and regular-expression members, and more.
- **Items come from every imported file.** A `ProjectReference` or `PackageReference` in an imported `.props` was
  dropped, and items were not expanded with the properties as they end up.
- **Central package management is complete.** `CentralPackageTransitivePinningEnabled` pins the packages the project
  gets through others, and `GlobalPackageReference` items reach every project.
- **What packages' targets do before the compiler runs is done.** A target that turns `.resx` files into
  `AdditionalFiles` (ResxSourceGenerator, ThisAssembly.Strings) gives the generator its files and metadata, as
  MudBlazor's localization needs; a target that removes another package's generator, as
  Microsoft.Extensions.Telemetry.Abstractions removes the logging generator it replaces, removes it (eShop's CS0757);
  assemblies a package's targets reference by `HintPath` are referenced (MSTest's `TestContext`).
- **Packages' source files compile as NuGet adds them.** `contentFiles` sources of the packages a project references
  compile into it, `.cs.pp` files preprocessed, and not those of packages it only gets through another package, as
  NuGet's default for a package's dependencies leaves them out; a manifest's `buildAction` is honored. A package's
  `frameworkReferences` add ASP.NET Core to the projects that get it.
- **A project referenced with `PrivateAssets="all"` keeps its packages to itself**, so MudBlazor's analyzer projects
  no longer give their Roslyn version to the projects that reference MudBlazor (NU1107).
- **Extern aliases work.** A `ProjectReference`'s `Aliases` put it under `extern alias`, as MudBlazor's analyzer tests
  and refit's tests need.
- **Every project gets the additional files it lists**, not only the first project that lists a shared one
  (StronglyTypedId's templates, 199 errors).
- **The SDK's preprocessor symbols are all defined**, `NETCOREAPP3_0_OR_GREATER` and the other `NETCOREAPPx` ones
  included (markdig's polyfills).
- **Embedded resources are named as the SDK names them**, from `LogicalName` and `Link`; MSTest.Sdk projects get
  MSTest of the version `global.json` pins; a project's own `AvaloniaXaml` items are compiled; generators see the
  SDK's `RootNamespace`, `AssemblyName` and target framework.
- **A solution's build configuration is honored.** A project the solution's Debug configuration does not build
  (no `Build.0` in a `.sln`, `<Build Project="false" />` in a `.slnx`) is left out of builds, as Visual Studio leaves
  it out, unless a project that is built references it.
- **`IsTestProject` set to `false` is honored**, so RestSharp's interactive tests are a program, not tests.

### The startup project is the one a person would choose

- Avalonia's cross-platform template starts its **Desktop** head, not its Browser head.
- eShopOnWeb starts **Web**, the server, rather than BlazorAdmin, the Blazor WebAssembly client it hosts, which it
  called Ready.
- A solution's Python docs or Node tooling is no longer its startup project when it has .NET programs.
- A program that is left out of builds is never the startup project.

### The Compatibility Doctor explains what cannot be built here

What needs something TabStudio cannot have is one line in the Doctor, and its project is left out of builds, instead
of hundreds of errors: a project that targets .NET 11 (it names the SDK that builds it), a browser head compiled ahead
of time to WebAssembly (it needs the wasm-tools workload), a project that generates its gRPC code with protoc, and a
project built with the Aspire AppHost SDK. A project that compiles against one of these is left out with it, and the
Doctor names the project it needs (eShop's Basket tests: "it compiles against Basket.API, which generates its gRPC and
Protocol Buffers code with protoc"). A project the solution does not build says so.

### Programs that call `Environment.Exit`

A program that calls `Environment.Exit` or `Environment.FailFast` ends with its exit code, and TabStudio keeps running:
the calls are redirected when the program is compiled to run, and the Error List shows a warning instead of the error
that stopped the build (SimpleDrawingApp).

## Still to do

TabStudio compiles every project against .NET 10 with Roslyn 5.0, the compiler it ships. A project that targets an
older .NET and uses an API .NET 10 changed shows the difference (TodoApi's `UserLoginInfo`, 1 error), a .NET Framework
library that uses `System.Data.SqlClient` from the framework does too (Dapper.EntityFramework, 2), and C# that only a
newer compiler accepts, such as collection arguments `[with(...)]`, fails (refit's analyzers, 25). Generated code that
a package's MSBuild task writes, rather than a source generator, is still missing: Microsoft.Testing.Platform's
`SelfRegisteredExtensions` (Terminal.Gui, 9), TypeNameFormatter's and IFluentInterface's copied sources and
ThisAssembly's strings (moq, 16), and ReactiveUI's generated fields in Dock's ReactiveUI.Reactive models (43).

## Install

1. Download `TabStudio-0.20.3.apk` below on your tablet.
2. Open it and allow installing apps from your browser or file manager when Android asks.

Requires Android 9 or later on 64-bit or 32-bit ARM, with 3 GB of memory or more (2 GB with TabStudio Link). It installs
as an update over earlier 0.20 releases.

## Verified

Every commit runs the unit tests of every library, headless UI tests of the real IDE in both themes, an APK build with
signature verification, and the full self test on an Android tablet emulator. Each fix above came with a test that
failed before it. The real-repositories job now opens and builds 29 more .NET solutions, each pinned to a commit with
its error baseline: those of the earlier sweep (refit, Mediator, StronglyTypedId, spectre.console, MVVM-Samples,
TodoApi, ContosoUniversity, MudBlazor, eShop, .NET MAUI's TodoSQLite, Dock and Terminal.Gui) and seventeen more
(Dapper, CsvHelper, Scrutor, markdig, scriban, NSubstitute, moq, Mapster, RestSharp, Ocelot, NodaTime, the .NET
Community Toolkit, Jason Taylor's Clean Architecture, Ardalis.Specification, AutoFixture, YamlDotNet and Bogus). Each
was also built with the .NET 10 SDK to know the errors Visual Studio shows. The table of errors and startup projects
before and after, for every solution, is in the pull request that made this release.
