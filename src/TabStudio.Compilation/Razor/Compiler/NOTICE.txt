The Razor compiler inside TabStudio
===================================

This folder holds the Razor source generator of the .NET SDK, unchanged. TabStudio runs it inside Roslyn the
way the SDK does, so .razor and .cshtml files compile on the tablet.

Origin
------
The files come from the .NET SDK 10.0.113 (sdk/10.0.113/Sdks/Microsoft.NET.Sdk.Razor/source-generators/), built
from the dotnet/dotnet repository (src/razor) at commit 4099f83977f4d29604a9aeb971fb0a7bc1d5f699, informational
version 10.0.0-preview.26504.104. No stable NuGet package carries this compiler, so the SDK's own build is used.

  Microsoft.CodeAnalysis.Razor.Compiler.dll         10.0.0.0   sha256 40640637e2cb3ece116b9aef405c9c83dde01759a489dae3a2ce8afd4e4fa104
  Microsoft.AspNetCore.Razor.Utilities.Shared.dll   10.0.0.0   sha256 3d5c83b7c09f84a6ffe39172e04fe82b7598e59970bb5e8f9d33a6943e9e41b8
  Microsoft.Extensions.ObjectPool.dll               8.0.0.0    sha256 6a06631ff0962f03f142732c4735ee69f563deb7af8c55467c33c35663887b36

Why this version
----------------
A source generator can only run inside a Roslyn at least as new as the one it was built against. The SDK's
10.0.1xx feature band builds Razor against Microsoft.CodeAnalysis 5.0, the version TabStudio pins in
Directory.Packages.props. Newer feature bands (10.0.2xx and later) build it against newer Roslyn versions and
would not load. Update these files together with Microsoft.CodeAnalysis, from an SDK whose
sdk/<version>/Roslyn/bincore/Microsoft.CodeAnalysis.dll has the same major and minor version, with
build/razor/update-razor-compiler.sh.
